# 模型中心：模型从哪来、给谁用

**「设置 → 模型中心」**（Settings → Model Hub）是配置模型的唯一入口：一个模型服务（接口地址 + API Key）只在这里加一次，再按模型决定给 Claude、dimensio 还是 Media Studio 用。以前分散在三处的配置——设置 › Claude 里的「自定义 API」、dimensio 自己加的模型服务和它那几家厂商的 Key、Media Studio 的媒体服务——都并到了这里（老配置怎么过来的见最后一节）。

Claude 订阅（Pro / Max）不在这里配：订阅账号在「设置 → Claude」的订阅号池里管，这一页只是把它们列出来。

## 在哪、谁能看到

- 设置根页「Agent」分组里，排在各个 agent 之后、「Agent 接入」之前的 **「模型中心」**（Model Hub）一行。Windows 桌面客户端里是设置左栏的同名分区，和 Claude、dimensio 并排。
- **管理员**看到的是整台服务器的总览，能添加、修改、删除服务。
- **注册账号（成员）**点进去只有自己的那一份——**「我的服务」**（My providers），见下面「成员看到的」。成员不能用 Claude 时没有这一行。
- 别处的入口都通到这里：dimensio 的「模型服务」面板里点「＋」直接打开这里的添加页，点卡片上的铅笔打开它在这里的那个服务；「设置 → dimensio」里也有一行 **「模型中心」**。

## 管理员的总览页

从上到下：

1. **种类筛选条** —— **「全部」**（All）、**「文本」**（Text）、**「图像」**（Image）、**「视频」**（Video）、**「配音」**（Voice）、**「音乐」**（Music），只看有这一类模型的服务；右边是 **「添加服务」**（Add provider）。一个服务都没有时，页面上只有一张线稿和「添加服务」按钮。
2. **服务卡**，一行一个来源：
   - **模型中心的服务**：品牌标、名字，下面一行是域名和各类模型的数量（如「文本 12 · 图像 3」）；行尾的小图标表示它的模型给了谁（Claude / dimensio / Media Studio），再往右是启停开关。点这一行打开它的详情。
   - **Vertex AI** 一行：Google 云上的 Gemini，见下面「Vertex AI」。没配凭据时标着 **「未配置」**（Not set up），没有开关。
   - **插件提供的模型**：标着「插件」和插件名，只读——地址和账号在那个插件自己的面板里管。
   - 标着 **「待交给模型中心」**（Not in Model Hub yet）的行：升级时没能自动并进来的老配置，点它按提示交给模型中心即可（见最后一节）。
3. **「Claude 订阅账号」**（Claude subscription accounts）一组：订阅号池里的每个号，写着 5 小时和每周各用了多少、套餐，正在用的那个标着「使用中」。点一行跳到「设置 → Claude」去管（加号、排序、自动换号都在那里，见 06-users-admin.md「Claude 账号」）。

筛选选了图像、视频这类媒体时，订阅账号这一组会收起（它们都是文本模型）。

服务行上可能出现的标记：

| 标记 | 意思 |
|---|---|
| **「已停用」**（Disabled） | 开关关着，它的模型在各处都选不到 |
| **「缺 Key」**（No key） | 没有一把启用着的 Key，要点进去补 |
| **「线路已全部停用」**（All routes disabled） | 里面的 Key 全被单独关掉了 |
| 「N 条线路冷却中」 | 有 Key 刚撞了限额 / 余额不足 / 被拒，暂时跳过（见「多把 Key」） |
| **「未添加模型」**（No models added） | 服务建了，但一个模型都没勾 |
| **「没给任何 agent」**（Not given to any agent） | 勾了模型但没选去向 |
| **「已共享给成员」**（Shared with members） | 成员也能用（见「共享给成员」） |

## 添加一个服务

在 Muse 上，**先放行这个网站再加**（见下面「在 Muse 上要注意」），否则第二步会一直等到超时。

1. 点 **「添加服务」**（Add provider）。最上面一排 **「快捷选择」**（Quick picks）是常见提供商：OpenRouter、OpenAI、Anthropic、Gemini、DeepSeek、硅基流动、阿里云百炼、智谱 GLM、Kimi Code、Kimi、火山方舟、MiniMax、小米 MiMo、xAI、Mistral、Groq、Together AI——点一个只是把它的接口地址填好。不在这一排的服务，自己把地址填进 **「接口地址」**（Base URL）就行，贴完整的请求地址也可以，会自动截到根。
   - Kimi 有两个：**Kimi Code** 是订阅用的那个端点（`sk-kimi-` 开头的 Key），**Kimi** 是开放平台，两边的 Key 不通用，别选错。
2. 把 Key 填进 **「API Key」**（API key），点 **「识别模型」**（Detect models）。服务器会去这个地址试出接口类型（OpenAI / Anthropic / Gemini）并拉回模型清单，最长等 45 秒。
3. 识别出的模型按 **文本 / 图像 / 视频 / 配音 / 音乐** 分栏，每栏写着数量。模型多时用 **「搜索模型」**（Search models）、**「按模型厂筛选」**（Filter by vendor）找，表头的 **「全选」**（Select all）勾当前筛出来的全部。清单里没有的模型，在列表底部点 **「手动添加模型 ID」**（Add model ID manually）。
4. 勾上要用的模型，底部升起操作条：左边「已选 N」，右边 **「添加到」**（Add to）后面是去向——文本模型是 Claude 和 dimensio，媒体模型是 Media Studio——点亮要给的，再点 **「保存」**（Save）。第一次保存就把服务建好了，页面不关，可以换一栏接着加。
5. 已添加的模型排在各栏最前，行尾有它去了哪儿的小图标。想撤掉：勾上它、把去向取消点亮、保存。

几条限制，界面上会写明原因（行尾 **「暂不支持」**（Not supported），或操作条上一句话）：

- Gemini 接口的服务给不了 Claude，只能给 dimensio；模型 ID 里有 Claude 不认的字符、上下文窗口不到 4096 的也给不了 Claude。
- 向量、识别一类的模型不能添加。
- 媒体模型只能给 Media Studio，而且要这台服务器开着 Media Studio、它接得了这个服务的这一类模型（见 09-media-studio.md）；文本模型不能给 Media Studio。
- 上限：最多 40 个服务，每个服务最多 100 个文本模型、30 把 Key。

识别不出来时：

| 页面上写的 | 多半是 |
|---|---|
| 「…在 45 秒内没有回应」「连不上 …」 | 在 Muse 上通常是这个网站的审核卡还没批（见「在 Muse 上要注意」）；其次才是地址填错 |
| 「Key 无效：… 拒绝了这个 Key（401 / 403）」 | Key 填错、过期，或 Key 和端点不是一家的（比如把开放平台的 Key 填给了订阅端点） |
| 「列不出模型清单，可以手动添加模型 ID」 | 这个服务不提供模型列表接口，不算失败：手动填模型 ID 照样能用 |

## 加好之后在哪儿选

- **Claude 页**：模型菜单的「More models」里，按服务分组。
- **dimensio 页**：模型胶囊的菜单里；它的「模型服务」面板里对应多一张卡，卡片只管切换，添加和修改都回到模型中心。
- **Media Studio**：对应创作页的模型菜单里。
- 停用服务（总览页的开关，或详情里的 **「启用这个服务」**（Enable this provider））后，它的模型在这几处都选不到；正在用它的对话会报这个服务已停用，换个模型再发。

### dimensio 有专门适配的几家

Anthropic、DeepSeek、Qwen（阿里云百炼）、智谱 GLM、Kimi（订阅端点 `api.kimi.com`）、小米 MiMo、Gemini 这七家，dimensio 对它们各有一套专门的调用方式。它们现在也是模型中心里的普通服务，以前「dimensio 内置厂商」那一组和 dimensio 设置里逐家填 Key 的地方都没有了：

- 添加时按接口地址认出是哪一家；把模型勾给 dimensio 后，详情页上会写「dimensio 对这家厂商有专门适配：添加给它的模型直连官方接口，用第一条可用的 Key」。
- 思考档位、型号规格、联网搜索这些都和以前一样，旧对话和默认模型不用重选。
- 同一家只认一个服务（排在前面的那个）。同一家加了两个服务时，dimensio 的专门适配只用第一个。

## 改一个服务：连接、多把 Key、测试、删除

点服务行打开详情，顶栏名字下面一行写着「域名 · 接口类型 · Key 尾号」。点 **「连接设置」**（Connection settings）展开连接面板：

- **「名字」**、**「接口地址」**（Base URL）。改了地址保存后会自动重新识别；只换 Key 的话页面会提示建议重新识别。接口类型建好后不能改，要换就删掉重加。
- **「API Key」** 一栏列着每一把 Key：标签（自己起名）、尾号、单独的启停开关、**「更换」**（Replace）、**「测试」**（Test）、移除。**「添加 Key」**（Add key）再挂一把。界面上只显示 Key 的末几位。
- 有两把以上时出现 **「多把 Key 的用法」**（Key rotation）：**「按顺序」**（In order）总是先用第一把，它不行了才用下一把；**「轮流」**（Round robin）几把轮着用。
- **「测试」** 用这把 Key 真发一次很小的请求，通了显示「通了，N 毫秒」，不通写原因。要先添加过至少一个文本模型才能测。
- **「走出站代理」**（Use outbound proxy）、**「启用这个服务」**（Enable this provider）、**「共享给成员」**（Share with members）——最后这个只在多人模式下才有——三个开关。
- 改完点 **「保存连接」**（Save connection）；**「重新识别」**（Detect again）重拉一遍模型清单（新出的模型这样才看得到）。
- **「删除服务」**（Delete provider）：确认后，它已经添加到各处的模型一并移除，不能撤销；正在用它的对话要换模型。

### 一把 Key 不行了会怎样

请求发出去后，上游回「Key 无效 / 被拒绝」（401、403）、「余额不足」（402）、「限额」（429）或者连不上时，这把 Key 进入冷却，同一个请求自动换下一把重发；都不行才把最后的报错交回对话里。冷却时长大致是：限额约 1 分钟（上游给了重试时间就按它的），Key 无效或被拒约 30 分钟，余额不足约 6 小时。

- 冷却中的 Key 在连接面板里写着原因和大约多久后再试；充了值、换了额度不想等，点旁边的 **「现在就再用」**（Use now）。
- 冷却状态只记在内存里，服务重启就清零。Claude 和 dimensio 共用同一份状态。
- 回答已经开始往回流之后不会再换 Key；流到一半断了，由对话自己重试。

## 共享给成员

多人模式下，管理员在服务的连接面板里打开 **「共享给成员」**（Share with members），总览页这一行标上 **「已共享给成员」**（Shared with members）。

- 成员的 Claude 模型菜单「More models」里出现这个服务的模型；他的模型中心页底下多一组 **「管理员共享给你的服务」**（Providers shared with you by the admin），每行标着 **「管理员共享」**（Shared by admin），只读。成员的 dimensio 里也能选到勾给了 dimensio 的那些模型。
- 用的是**管理员的 Key**，钱记在管理员在那家服务的账户上；同时计入这个成员在本站的额度（按轮数算，第三方模型的金额算不准，花费记 0）。
- 成员看不到接口地址和 Key，改不了、删不了、测不了。
- 关掉共享或停用服务后，成员那边立刻消失，正在用它的对话要换个模型再发。

## 成员看到的

成员没有总览，他的「模型中心」页是：

- **「我的服务」**（My providers）：他自己给 **Claude 页**接的模型服务，用自己的 Key、花自己的钱，不占本站额度；最多 10 个，只能填公网地址。**「添加服务」**（Add provider）先出一页预设（DeepSeek、Kimi、OpenRouter 等，只是填好地址和协议），或选 **「从头配置」**（Start from scratch）；编辑器里填 **「接口地址」**（Base URL）、**「接口协议」**（API protocol）和 Key，点 **「从服务拉取」** 拿模型列表或 **「手动添加」**，**「检测连接」**（Check connection）能试出地址和协议对不对。成员的编辑器和管理员的不是同一个，没有「识别模型」和分栏。
- **「管理员共享给你的服务」**：见上一节。
- 开了 dimensio 的话还有一行 **「dimensio 的模型服务」**（dimensio model providers），点了跳到 dimensio 里他自己那一份。

管理员和每个成员的服务互相看不到。

## Vertex AI

总览页的 Vertex AI 一行是 Google 云上的 Gemini（Gemini 4 Carbon、Gemini 4 Argon 等），给 Claude 和 dimensio 当对话模型用。它要**用户自己的 Google 云项目和凭据，费用由 Google 按用量收**。点开这一行：

- 最上面是 **「Google 云凭据」**（Google Cloud credentials）卡：上传凭据 JSON、填项目 ID，存完立即生效。怎么拿凭据、测试报错怎么看、要放行哪几个 Google 的网站，都在 09-media-studio.md；Muse 要做的在 `../MUSE.md` 4.9。**凭据文件的内容别发在 Muse 的聊天里**，直接在这张卡上传。没配好之前，下面的型号不会出现在任何地方。
- **「启用」**（Enable）开关；多人模式下还有 **「共享给成员」**（Share with members）——打开后成员也能选这些型号，费用记在服务器这个 Google 云项目上，默认关。
- **「提供给」**（Available to）：勾 Claude、dimensio。
- **「型号」**（Model）：勾要列出的 Gemini 型号；列表里没有的，在下面的输入框填型号 ID 回车添加。
- **「媒体模型」**（Media models）——开着 Media Studio 时才有：Vertex 上的图像、视频、配音、音乐模型在这里逐个开关，打开的出现在 Media Studio 里。还没有这一组时，点 **「加上 Vertex 的媒体模型」**（Add Vertex media models）。
- 改完点底部 **「保存」**（Save）。加好后 Claude 页在「More models」的 Vertex 一组里选。

## 在 Muse 上要注意

- **先放行网站，再加服务**。这台 VM 只能经 Muse 的出站代理上网，每个新网站都要用户在 Muse 的审核卡上批（卡片在输入框上方或右侧「待审核」面板）。加服务之前让 Muse 跑 `allow-sites <接口地址>`，用户批了再回网页点「识别模型」。没放行时，识别、测试和之后的对话都会一直等到超时。审核卡有「允许一次」「总是允许此站点」和拒绝几种选法，各自的后果在 `../MUSE.md` 2.0——照实告诉用户，由他自己选：只选「允许一次」的话，服务以后在后台再访问这家时还会再弹卡，没人批对话就停在「等待模型回复」。
- **「走出站代理」要保持打开**。这个开关默认开着；它是给本机或内网模型直连用的，而这台 VM 不能直连外网，关掉后这个服务的请求发不出去。看到识别 / 测试一直连不上，顺便看一眼它是不是被关了。
- **本机模型在 Muse 上没有**。Ollama 这类跑在自己电脑上的模型，地址是本机或局域网地址，这台 VM 连不到；总览里如果出现「本机图像模型」一行，也用不了（VM 没有显卡）。
- **Key 存在哪**：加密存在这台 VM 的数据目录里（`/home/hatch/bridge-srv/model-hub/`），不回传浏览器，界面和报错里都只出现末几位。
- **key 由用户自己在网页的模型中心里填**，key 不经过聊天。`bootstrap.sh set-api-key` 在模型中心接管之后（升级或新装后第一次启动就接管了）对管理员的 dimensio 不再生效，命令输出会照实说；它仍会先访问一次这家的接口网站、把审核卡弹出来，所以放行这一步 Muse 用 `allow-sites <接口地址>` 就行（`../MUSE.md` 4.5）。用户已经把 key 发在聊天里的话，提醒他删掉那条消息。
- 成员自己的服务（「我的服务」）一律经出站代理，编辑器里没有代理开关；成员加之前同样要先请管理员让 Muse 放行那个网站。

## 从旧版本升级上来

服务器更新到带模型中心的版本后，**第一次启动会自动把老配置并进来**，不用手动搬：

- **设置 › Claude 的「自定义 API」**（管理员的那些）：地址、Key、模型照原样成为模型中心的服务；原来那份只是从模型菜单里藏起来，**正在用它的老对话照常能接着聊**，不用重选模型。
- **dimensio 自己加的模型服务**：同样照搬，原件留着给老对话用，从 dimensio 的「模型服务」面板里藏掉。
- **dimensio 那几家厂商的 Key**（网页里填的、以及以前用 `set-api-key` 写的）：每家变成模型中心里的一个服务，模型只勾给 dimensio，用法不变。
- **Media Studio 的媒体服务**（地址 + Key 的那种）：原地交给模型中心管，作品和任务历史不受影响。
- 模型中心里已经有同一个服务（同一个地址、同一把 Key）时并进那一个，不会多出一张重复的卡；名字撞了的会在后面标上来路。
- 一个服务的模型超过 100 个时，先添加前 100 个，其余留在模型列表里，勾上就能加。
- **成员自己的服务不动**，还在他自己的「我的服务」里。
- 改动前留了备份：数据目录 `model-hub/` 下的 `services.pre-native.bak.json`、`services.pre-unify.bak.json`。

个别没并成的（比如 Key 存储当时读不出来）下次启动会再试；期间它在总览页标着 **「待交给模型中心」**（Not in Model Hub yet），点它会问一句 **「改为共用」**（Make shared）或 **「交给模型中心」**（Hand over to Model Hub），确认后照抄成模型中心的服务并打开它。从 dimensio 交过来的那种，原来那份会从 dimensio 里删掉，正用着它的对话要重新选一次模型。

升级后发现某个模型不见了：先到模型中心看那个服务是不是停用、缺 Key，或模型没勾给对应的 agent；都对还是没有，按 `../MUSE.md` 第 8 节判断要不要报告。
