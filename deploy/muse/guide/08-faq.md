# 常见问题与现象速查

先跑一次 `bash /home/hatch/bridge-ops/bootstrap.sh known-issues`：用户说的现象如果在已知问题里，直接告诉他绕过办法（`../MUSE.md` 第 8 节）。

## 对话一直转圈 / 停在「等待模型回复」「等待 Claude…」

按顺序排查：

1. **Muse 里有没有没批的审核卡**（最常见）。这台 VM 访问每个新网站都要用户在 Muse 里批准，卡片是「允许 Muse 与 <网站> 分享信息？」，可能在 Muse 输入框上方，也可能在 Muse 右侧的「待审核 / Needs review」面板里。没人批，对话就一直等。让用户去批，选「允许一次」旁边下拉里的「**总是允许此站点**」；或者你在用户在场时跑 `allow-sites`，把要用的网站挨个弹出来让他批。
2. **Claude 页**：令牌没配或失效——发一条消息就会看到红字提示（见 02-claude-code.md 最后的表）；订阅额度用完——会提示恢复时间。
3. **dimensio**：这家厂商没配 key，或者 key 不对（见下面「dimensio 换了 key 不生效」）。
4. 服务本身挂了：跑 `status --local` 看，按 `../MUSE.md` 第 7 节处理。

## 审核卡片是什么、为什么老弹

- 是 Muse 平台的安全机制：VM 上的程序第一次访问某个网站时，要用户批准一次。Muse Bridge 装好时已经把常用的网站（Claude 接口、搜索、反馈服务、配了 key 的模型厂商）挨个弹过一遍。
- 选「总是允许此站点」之后，这个网站以后就不再问（包括它的子域名）。批错了可以在 Muse 的设置 → 权限里撤销。
- 什么时候还会弹：新加一家模型 key、加自定义模型服务（Claude 页的自定义 API、dimensio 的自定义服务）、装连接器 / 插件、第一次拉取官方扩展市场（github.com）、agent 第一次访问某个新网站。提前用 `allow-sites <网站>` 放行最省事。
- 你（Muse）看不到卡片，也替用户批不了；只能提醒他去批。

## 地址变了 / 打不开了 / App 连不上

- 用临时地址时，VM 每隔几个小时重启一次，地址会变。跑 `status` 拿新地址告诉用户；令牌不变，但**新地址要重新登录一次**。App 里点「更换地址」粘新地址。
- 旧地址打开是 Cloudflare 的 530 错误页，说明地址已经换了。
- 不想老换：换成自己的域名（`../MUSE.md` 第 5 节），以后地址固定。
- 地址没变也打不开：`status` 看服务状态，按 `../MUSE.md` 第 7 节排查。

## VM 重启了会怎样

- 平台每隔几个小时会重启这台 VM。看门狗会在几分钟内自动把服务拉起来，临时地址会变（你会收到通知去告诉用户）。
- 重启时正在跑的对话会被打断：Claude 页会提示「这一轮被中断」，说一句「继续」就行；dimensio 会自动接着做，但要等有人打开一次 dimensio 页面。对话记录都在。

## dimensio 换了 key 不生效

- 内置厂商的 key 有两个来源：Muse 用 `set-api-key` 写进服务器的，和用户在 dimensio 侧栏「设置」里填的。两种都存在磁盘上，重启不会丢。
- **网页里存过的 key 优先**，而且界面上清不掉（留空 = 不改）。所以网页里填过一把错的 / 过期的 key 之后，再跑 `set-api-key` 也不起作用：让用户在 dimensio 的「设置」→「API Key」里把对的 key 再填一次、点保存。
- 以后同一家只用一种方式配，首选 `set-api-key`（`../MUSE.md` 4.5）。

## 额度环的读数为什么慢

- Claude 页输入框旁的用量环（订阅 5 小时 / 每周额度）最多约 10 分钟才刷新一次，服务器不再主动去探测。刚用掉很多额度时读数可能比实际慢一点；真撞上限额时会直接弹出限额卡并写明重置时间，可以开「限额重置后自动继续」。

## PR 卡提示没装 gh / 请登录

- Claude 页的拉取请求（PR）功能要用这台 VM 上的 GitHub CLI：卡片提示「未安装 GitHub CLI（gh）」或「请运行 gh auth login 登录」时，请 Muse 在 VM 上装好 gh 并登录（登录要用户在场操作），还要放行 github.com（`allow-sites github.com`）。详见 02-claude-code.md「拉取请求」。

## 要花钱吗

- Muse Bridge 本身免费开源。
- Claude Code 用的是用户自己的 Claude 订阅（Pro / Max），额度按订阅算，所有登录的人共用这一份。Claude 页接的别家模型（自定义 API）按那家的价格计费。
- dimensio 用的是各家的 API key，按各家价格计费（dimensio 里不显示金额，去各家控制台看）。小米的联网搜索插件另外按次收费。
- Muse 平台本身的费用以 Muse 为准。

## 数据存在哪、安全吗

- 所有文件、对话记录、配置都在这台 Muse VM 的 `/home/hatch/bridge-srv/` 里。管理员的文件在 `workspace/`，每个注册账号的在 `users/<账号名>/`。
- 外网访问经过 Cloudflare 隧道（https）。地址谁拿到都能打开登录页，但没有令牌或账号进不去。
- 你跟 agent 聊的内容会发给对应的模型厂商（Anthropic、DeepSeek 等）。Claude Code 的遥测、错误上报这类非必要流量已经关掉。
- 网页里「提交反馈」写的东西只留在这台服务器上。给 Muse Bridge 开发者的问题报告只含版本、服务状态和程序自己的报错，不含对话、文件、key、地址，而且要用户看过草稿、同意了才发（`../MUSE.md` 第 8 节）。
- **管理员默认只能看到成员的会话标题、时间和用量**；看对话正文、代聊代答要成员自己在「设置 → 账户 → 管理员可见性」里允许，每次查看都有记录。但技术上服主仍能读到服务器上的文件，完全信任账号有命令行、等同管理员。只给信任的人开账号。
- 这是 Muse 的 VM，不是正式服务器：别放重要数据，也别当生产环境用。

## 怎么备份、导出

- 单个文件：工作空间里 **「下载到本地」**（Download）。
- 整个文件夹：在工作空间里对文件夹点 **「压缩…」**（Compress…）打成压缩包再下载；或者在回答里把文件夹作为结果给出来，点卡片上的 Download（会打成 zip）。
- 对话：界面上没有导出按钮。可以让 Claude 把对话要点整理成文件再下载。
- 全部数据：你可以在 VM 上把 `/home/hatch/bridge-srv` 打包给用户下载，但里面有 API key、令牌哈希这些敏感信息，提醒他私下保存。

## 删错了能找回吗

- 工作空间里的删除是**永久的，没有回收站**。
- Claude 改坏 / 删掉的文件：Claude 页用户消息下面的「回滚」可以把 Claude 之后的改动退回去。
- dimensio 改坏的：顶栏「回滚到检查点」，或工作区「审阅」里撤销单个文件。
- 删掉的对话找不回来。不想看见但不想删的对话，用 **「归档」**（Archive）：在侧栏底部的 **「已归档」** 里能找回、取消归档。
- 临时对话 30 天没动会先进 **「回收站」**，再放 30 天才永久删，期间能 **「恢复」**；想一直留着就点 **「存为工作空间」**。

## agent 能不能打开网页、截图、操作浏览器

- 不能。这台 VM 起不了浏览器（平台限制），所以没有浏览器工具和截图。
- 联网搜索、抓取网页文字内容照常可以用。
- 做网页时 agent 可以写好文件，用户在「工作空间」里点 html 文件直接预览（脚本和动画都会跑）。

## 收不到通知

- 「设置 → 通用 → 通知」是总开关，默认开着。但网页不会主动向浏览器要通知权限：到浏览器的网站设置里（地址栏左边的图标）把这个网址的通知改成「允许」。以前点过「禁止」的也在那里改。
- 页面正开着、你正看着时不通知。Claude 页在跑完、等你批准、等你回答时通知，每一类可以在「设置 → Claude → 通知」里单独关（只管这台设备）；dimensio 等你批准 / 回答时也会通知。

## 定时任务的时间不对

- 定时任务按服务器时区跑，页面上写的「GMT+8」不准；Muse 的 VM 一般是 UTC，比北京时间晚 8 小时。想北京时间 9 点跑就填 01:00。不确定就跑 `date` 看服务器时间。（已知问题）

## 用临时地址时终端连不上、dimensio 不逐字出

- Claude 页的终端一直「连接终端…」、dimensio 的回复要等整段做完才出来：临时地址的已知限制。换成自己的域名就正常。

## 手机上能用吗

- 能。安卓装 App，iPhone 用 Safari 添加到主屏幕，见 01-access.md。手机上回车是换行，发送要点按钮。

## 电脑上能用桌面客户端吗

- 能用 bridge 的 Windows 桌面客户端连这台服务器。**绑了自己的域名（固定地址）才有完整的桌面体验**：标题栏、快问浮窗、把电脑登记成设备让 Claude 操作（见 07-settings.md「设备」）；用临时地址时客户端只当网页窗口用。没有特别需要的话，浏览器打开就够了。

## 能不能加别的 agent（Codex、Gemini CLI……）

- Muse Bridge 只有 Claude Code 和 dimensio 两个（不带 Codex、Gemini 这些扩展）。想用别家模型：在 dimensio 里配那家的 key，或用「自定义服务」接 OpenAI / Anthropic / Gemini 接口；想在 **Claude 页** 里用 DeepSeek、Kimi、OpenRouter 这类模型，在「设置 → Claude → 自定义 API」里接（见 07-settings.md）。

## 能同时跑几个任务

- Claude：每个账号最多同时 3 个对话在跑。dimensio：同一个浏览器最多 3 个。
- 关掉浏览器任务照样在服务器上跑，回来能接上。
- Claude 还在回复时也能继续发消息：Enter 是「插话」（它下一步就读到），Ctrl+Enter 是「稍后发送」（排队，这一轮结束后发）。

## 怎么更新

- 有新版本时 Muse 会告诉用户更新了什么，用户说「更新」就更新；也可以开自动更新。更新会等没人在聊时才切换，起不来会自动退回旧版本（`../MUSE.md` 第 6 节）。控制台「服务控制」页里没有更新按钮，也是让他跟 Muse 说。
- 页面是服务器直接提供的，服务器更新后刷新页面就是新版，安卓 App 也一样。

## 想报 bug、提建议

- 直接跟 Muse 说：Muse 先判断是不是已知问题 / 配置问题，再出草稿给用户看，用户同意才发给开发者（`../MUSE.md` 第 8 节）。一句话就行，不用 GitHub 账号。
- 网页里的 **「设置 → 提交反馈」**（Settings → Send feedback）也能写，但在这台 Muse 上只留在服务器上（你能在 `/home/hatch/bridge-srv/feedback/reports/` 读到），不会自动发给开发者；用户想发给开发者，还是走上面那条。

## 怎么卸载

- 跟 Muse 说「卸载」：Muse 先确认，再停掉服务、删掉看门狗 hook 和程序；`bridge-srv` 里的数据会先问用户要不要删（`../MUSE.md` 第 6 节）。
