# 扩展：技能、连接器、插件

## 是什么

| 类型 | 是什么 | 能给谁用 |
|---|---|---|
| **技能**（Skill） | 一份写给 agent 的做事说明（`SKILL.md`，可以带脚本），比如「怎么写 Excel」「怎么做代码审查」 | Claude Code、dimensio |
| **连接器**（Connector） | 一个外部 MCP 服务，给 agent 增加工具（比如连 GitHub、数据库）。本地命令（stdio）或远程地址（HTTP / SSE）都行 | Claude Code、dimensio（dimensio 要在详情里勾上） |
| **插件**（Plugin） | Claude Code 专用的一整包：命令、子 agent、技能、钩子、MCP 打包在一起 | 只有 Claude Code |

**两个「市场」别搞混**（都在 **「设置 → 扩展」**（Settings → Extensions）里，但不是一回事）：

| | 在哪 | 里面是什么 | 装上之后 |
|---|---|---|---|
| Anthropic 的官方插件目录 | **「插件」**（Plugins）/ **「技能」** / **「连接器」** 标签里的 **「发现」**（Discover） | Claude Code 的插件、技能、连接器（Anthropic 和社区发布的几百个） | 给 agent 用：Claude 从下一条消息起多了这些命令、技能、工具 |
| bridge 的 **「插件市场」**（Plugin market） | **「功能扩展」**（Modules）标签里的「插件市场」一块 | Muse Bridge 自己的功能插件（bridge 官方发布并签名），以及内置功能的修复版 | 给这台服务器加功能、修毛病：不用等整个程序升级 |

用户说「装个插件」时先问清是哪一种：想让 Claude 会做某件事 → 官方插件目录；Muse Bridge 提示某个功能插件有更新 → 插件市场。

- **只有管理员能装、能管**。装的时候选生效范围（见下面「我自用 / 全服统一」）：
  - **「我自用」**（Just me）：只对管理员自己的对话生效（管理员的 Claude 对话、定时任务、dimensio）；
  - **「全服统一」**（Everyone）：给服务器上所有成员加装，注册账号的 Claude 会话和定时任务也会加载，管理员自己也用得上。
  - 注册账号看不到、改不了管理员装的这些；他们可以添加**自己的技能**（只有技能，见下面「成员自己的技能」）。
- 生效时间：Claude Code 从**下一条消息**起；dimensio 在**新对话**里。

## 怎么进

- **「设置 → 扩展」**（Settings → Extensions）：管理员在设置根页 **「服务器」**（Server）分组里；注册账号在 **「个性化」**（Personalization）分组里，点进去只有技能（见下面「成员自己的技能」）。手机、电脑上都能进。
- 也可以从 **「设置 → Claude → 扩展与记忆」**（Settings → Claude → Extensions and memory）进：里面是 **「技能」**（Skills）、**「连接器」**（Connectors）、**「插件」**（Plugins）三行，点哪行就直接打开那一类；同一页还有 **「定时任务」**（Routines）。
- Windows 桌面客户端里是设置左栏的 **「扩展」** 分区。
- Claude 页侧栏里没有扩展的入口。

### 我自用 / 全服统一

- 扩展页最上面有一个分段开关 **「我自用」**（Just me）/ **「全服统一」**（Everyone），每个后面带数量。列表、上传、从市场添加都按当前选的范围走。选「全服统一」时下面有一句说明，告诉你这里装的会给所有成员用。
- 这个开关**只有服务器开了多人使用时才出现**（没开多人时全服扩展只有你自己用得上；已经装过全服扩展的会照样显示，免得找不到）。多人开关见 06-users-admin.md。
- 全服连接器：所有成员调用它时用的都是你在这里填的同一份凭据（加密存在服务端，成员看不到），所以只装你愿意共享的。

## 成员自己的技能（注册账号）

- 多人模式下，注册账号也有 **「设置 → 扩展」**——在设置根页「个性化」分组里——也可以从 **「设置 → Claude → 扩展与记忆 → 技能」** 进，打开的是**只有技能**的扩展页，分 **「我的」**（Mine）/ **「发现」**（Discover）。
- 添加：**「上传技能」**（Upload skill）（`.md`、`.zip`、`.skill`，格式同下面「上传自己的技能」），或在「发现」里从官方市场一键添加技能。每个技能可以单独开关、选在 Claude 还是 dimensio 里用。
- 自己加的技能**只有自己看得到、用得到**，管理员也看不到；存在服务器上他自己的那一份里。
- 下面一组 **「服务器统一提供」**（Provided by the server）：管理员装在「全服统一」里的技能，直接可用，不能在这里改动。
- dimensio 里打 `/` 也能搜到这两类技能（自己的 + 全服统一的）；Claude 从下一条消息起、dimensio 在新对话里生效。
- 成员加不了连接器和插件，这两样仍只有管理员能装。

## 扩展页

- 四个标签：**「技能」**（Skills）/ **「连接器」**（Connectors）/ **「插件」**（Plugins）/ **「功能扩展」**（Modules）。前三个再切 **「我的」**（Mine）——装好的，和 **「发现」**（Discover）——可以装的。
- 搜索框、**「筛选」**（Filter）、**「排序」**（Sort），以及 **「添加」**（Add）菜单：**「上传技能」**（Upload skill）、**「添加连接器」**（Add connector）、**「上传插件」**（Upload plugin）、**「管理市场…」**（Manage marketplaces…）、**「刷新市场」**（Refresh marketplaces）；连接器标签的「添加」菜单里还有 **「添加 Figma（个人访问令牌）」**（Add Figma (personal access token)），见下面「在 Muse 上不能用 OAuth 登录的几家」。

### 「发现」：Anthropic 的官方插件目录

- 列的是 Anthropic 的官方市场（跟「功能扩展」里 bridge 的「插件市场」不是一回事，见上面；官方插件目录、知识工作插件、Agent Skills 三个来源，几百个插件，以及从里面拆出来的单独技能和连接器）。「筛选」里可以按来源、分类挑。
- 第一次打开「发现」时，服务器会自动从 GitHub 拉取市场（显示「正在从 GitHub 拉取官方市场…」）；以后点 **「刷新市场」** 更新。**「管理市场…」** 里还能添加别的 GitHub 市场（仓库里要有 `.claude-plugin/marketplace.json`）。
- **在 Muse 上第一次拉取可能弹 github.com 的审核卡**：没人批就会失败（页面上会写哪个来源没拉下来，有「重试」）。可以提前让 Muse 跑 `bash /home/hatch/bridge-ops/bootstrap.sh allow-sites github.com`，用户在场时把卡片弹出来批（选项见 `../MUSE.md` 2.0）。
- 每张卡片上的 **「添加」**（Add）就是装上（变成 **「已添加」**（Added））。外部仓库的插件添加时才从 GitHub 下载。第三方插件先看看它的主页再装。
- 需要填凭据的连接器（比如要填某个服务的 token）：添加后会打开编辑表单，填好才生效。凭据加密存在服务器上，存了就只显示 ••••••••，不改就原样保留。

### 「我的」：装好的

- 技能与插件卡片有开关和状态，比如 **「已停用」**（Disabled）、**「未对任何 agent 生效」**（Not active for any agent）。「筛选」里可以只看已启用 / 已停用的。
- 点开看详情：包含哪些东西、**「启用」**（Enable）开关、**「生效 Agent」**（Enabled for）——分别给 Claude Code、dimensio 打开或关掉；连接器使用下面介绍的连接状态与工具权限控制面板。
- 详情最下面的 **「管理」**（Manage）：**「替换」**（Replace）——上传新版本覆盖，保留开关和 agent 勾选；**「下载」**（Download）——打包成 zip 存到本地；**「卸载」**（Uninstall）——文件和保存的配置一起删，不可撤销。从市场整包装的插件还有 **「整包卸载」**（Uninstall bundle）。

## 上传自己的技能 / 插件、加连接器

- **技能**：`.md` 文件（开头的 YAML 里要有 `name` 和 `description`），或 `.zip` / `.skill` 包（里面要有 `SKILL.md`）。
- **插件**：`.zip`，里面要有 `.claude-plugin/plugin.json`。
- 上传时可以填 **「所属包（可选）」**（Bundle (optional)）：同包名的扩展归成一组统一管理。
- **连接器**（**「添加连接器」**）：填名称、描述（可选）和传输方式——
  - 本地命令（stdio）：启动命令、参数（一行一个）、环境变量（一行一个 `KEY=VALUE`）；
  - 远程 HTTP / SSE：服务地址、请求头（一行一个 `KEY=VALUE`）。远程连接器要求 OAuth 登录的话，添加后会直接打开官方授权页，不用先开对话，见下面「远程连接器授权」。
- 上传时会自动剔除 `.env`、私钥这类敏感文件。单个上传最大 64MB，扩展总数最多 200 个。
- 同名的已经装过时，到它的详情页用「替换」上传新版本（保留开关和配置）。
- 连接器要访问的新网站，在 Muse 上第一次用时也会弹审核卡；提前用 `allow-sites <地址>` 放行。

## 远程连接器授权（OAuth）

有的远程连接器要先登录对方的账号才能用。管理员在「发现」里点卡片上的「+」（添加）装上，或在 **「设置 → 扩展 → 连接器」**（Settings → Extensions → Connectors）用「添加连接器」加上之后，会直接打开它的官方授权页，不用先开对话；不需要登录的直接显示已连接。

1. 在官方页面登录、同意后回到 Muse Bridge。浏览器拦住弹窗时，点 **「打开授权页」**（Open sign-in page）。安卓 App 会交给系统浏览器。
2. **「我的」**（Mine）里，连接器按名称、类型和状态列成一张表：✓ **「已连接」**（Connected）、**「需要登录」**（Sign-in required）、**「授权失败」**（Authentication failed）（鼠标移上去看原因）、**「连接失败」**（Connection failed）。点「需要登录」可以重新授权；点名称进入它的控制面板。
3. 控制面板显示连接状态与工具数，可以 **「连接」**（Connect）或 **「断开连接」**（Disconnect）。断开会删掉这台服务器为这个连接器存的登录信息，需要时重新连接。「⋯」里还有 **「重新检测」**（Check again）、**「编辑配置」**（Edit configuration）、**「停用」**、**「卸载」**。
4. **「工具权限」**（Tool permissions）：工具分为 **「交互工具」**（Interactive tools）、**「只读工具」**（Read-only tools）、**「写入与删除工具」**（Write/delete tools），可为整组或单个工具选择 **「总是允许」**（Always allow）、**「需要批准」**（Needs approval）或 **「禁止」**（Blocked）。只对远程连接器有效，从下一条消息起生效；「需要批准」仍按会话权限模式处理。
5. 对话中的授权提示、会话信息面板里的「连接器」卡仍可使用。少数服务只接受本机回调时，按提示把带 `code=` 的完整回调地址复制回去，点 **「提交」**（Submit）。授权完，正在跑的会话也会自动重连。

要知道的：

- **在 Muse 上**：授权要服务器在后台访问对方的网站（换令牌、之后调用工具），第一次可能弹这些网站的审核卡。没人批的话，授权页跳回来后会一直转圈、最后失败。可以提前让 Muse 跑 `allow-sites <网站>`，用户在场时把卡片弹出来批（选项见 `../MUSE.md` 2.0）。**但报「平台（Muse）不允许在这里登录这个服务」（refresh_rejected）的不是审核卡的问题**，见下面「在 Muse 上不能用 OAuth 登录的几家」。
- **从平时打开 Muse Bridge 的那个地址点授权**：授权页要跳回这个地址。用临时地址的话，地址变了以后，进行中的授权会失效，重新点一次就行。
- **每个账号各授权各的**：令牌存在这个账号自己的目录里。成员在自己的对话里点「授权」，授权的是他自己的账号；管理员授权过不代表成员能用。
- 授权链接 10 分钟内有效、只能用一次；过期了重新点「授权」。授权失效（比如在对方那边撤销了）时会重新显示需要授权，再点一次就行。
- 手机窄屏上没有会话信息面板，入口就是输入框上方的提示，或扩展页里这个连接器的控制面板。

### 要自备 OAuth 应用的连接器（Gmail、Zoom 等）

有的服务（Gmail 等 Google 的连接器、Zoom）不让 Muse Bridge 自动注册登录客户端。这种连接器的控制面板显示 **「需要配置 OAuth 应用」**（OAuth app required），点 **「配置 OAuth 应用」**（Set up OAuth app）跳到面板里的 **「OAuth 应用」**（OAuth app）一节。

- **要管理员来配，全服配一次**：配好以后每个人点「连接」，登录的仍是他自己的账号。
- 照 **「注册步骤」**（Setup steps）去对方的开发者后台（Google Cloud 控制台、Zoom App Marketplace）注册一个应用：**「回调地址」**（Callback URL）和要加的权限范围都能一键复制（**「全部复制」**（Copy all））；把后台生成的 **「客户端 ID」**（Client ID）和 **「客户端密钥」**（Client secret）填回来，点 **「保存」**（Save），再点「连接」。
- **在 Muse 上，回调地址必须是这台 Muse 的公网地址**：回调地址是按你现在打开 Muse Bridge 的地址生成的，所以要从公网地址（`status` 给的那个）打开再配。用临时地址时，VM 重启后地址一变，后台登记的回调地址就对不上了，要回后台改、再回来重新保存——要长期用这类连接器，建议先换成自己的域名（`../MUSE.md` 第 5 节）。Google 只接受 https 域名的回调地址，不接受 IP。
- Gmail 等 Google 的 MCP 服务还在预览期：Google 要求先加入 Google Workspace 开发者预览计划（约两天审核）；测试模式下登录 7 天后失效，要回来重新连接。
- 填错了，连接时会说明去后台改哪一项（回调地址不一致、权限范围没加全、客户端 ID 或密钥不对）。不用了可以 **「删除应用」**（Delete app）。
- 在 Muse 上第一次连接，服务器换令牌时可能弹对方网站的审核卡，要用户批。

### 在 Muse 上不能用 OAuth 登录的几家（Figma、Stripe、Zapier）

- Muse 平台的出口代理会拦下这几家的换令牌请求。授权时报 **「这台服务器所在的平台（Muse）不允许在这里登录这个服务」**——报错里带 `refresh_rejected`。**这不是审核卡的问题**：批卡、重试、反复点「授权」都没用，别让用户再点。
- **Figma**：在连接器标签的「添加」菜单里点 **「添加 Figma（个人访问令牌）」**，装一个随 Muse Bridge 附带的 Figma 只读连接器（读文件、节点、导出图片、评论、组件与样式；改不了设计稿）。在 Muse 上不用在网页里填令牌：令牌交给 Muse 平台保管——请 Muse 建一个 API Key 型的自定义连接器，登记名 `custom.figma_pat`（网站 api.figma.com、请求头 `X-Figma-Token`），用户在 Muse 弹出的卡片里自己填 Figma 个人访问令牌（在 Figma 的 Settings › Security › Personal access tokens 里生成）。Muse Bridge 每次请求只拿平台给的替身，真令牌不进这台 VM。这个连接器是本地连接器，面板里显示「本地连接器 · 在对话里启动」，在对话里用到时才启动。**这是替代办法，还没在真 Muse 上从头到尾验证过**：用不了的话请用户报告问题（`../MUSE.md` 第 8 节）。
- **Stripe、Zapier 等其它被拦的服务**：没有现成的替代连接器。让用户直接跟自己 Muse Bridge 里的 Claude 说，让它按「这家服务的 API Key 或个人令牌 + Muse 平台的 `custom.*` 自定义连接器」的思路现写一个连接器（做法同上面的 Figma：令牌交给平台，连接器每次请求向平台要替身）；`custom.*` 的登记仍要请 Muse 来建，令牌由用户在卡片里自己填。这走的是 Muse 平台自己的凭据机制，不是绕过出口代理；别想办法绕开代理或让令牌进 VM。
- 报错提示里说的「Muse 设置 › 连接器 里平台自带的连接器」是给 Muse 自己用的，Muse Bridge 里的 Claude 调不到。
- 其它远程连接器（Slack、HubSpot、Intercom、GitHub、Google 的连接器等）照常授权；第一次连接时 Muse 可能弹对方网站的审核卡，要用户批。

## 「功能扩展」标签（一般不用动）

- 这里是 Muse Bridge 自己的功能开关，从上到下：
  - **Agent**：agent 扩展：dimensio 和 Gemini · Vertex。装、卸 dimensio 别在这里点，让 Muse 跑 `set-agents`（见 06-users-admin.md）；Gemini · Vertex 装好时关着，要用就在这里打开它的开关、再去配 Google 云凭据（见 09-vertex.md）。
  - **「功能」**（Features）：随程序一起装好的内置功能（定时任务、分享链接、设备、反馈……），按分类逐项开关。这台 Muse 装好时已经关掉了在 VM 上用不了的几项——手机操控、手机文件、内置浏览器、主机的 Edge、保持唤醒——**别把它们打开**，打开了也用不了。
  - **「插件市场」**（Plugin market）：bridge 官方发布、签过名的功能插件，一点就装；内置功能（定时任务、分享链接这些）的修复也可能从这里单独发。下载后逐个校验，对不上就不装。刚上线，里面的插件还很少。
  - **「已安装的插件」**（Installed plugins）：里面有一个 **Muse Bridge** 插件，它提供设置里的「安卓 App」那一页（下载 App、旧版 Muse App 的换装提示）和项目手册里的「Muse 部署」一章，**别停用、别取消登记**。用户自己要装第三方插件（**「上传 zip」**（Upload zip）、**「GitHub 地址」**（GitHub repo）→ **「从 GitHub 安装插件」**（Install a plugin from GitHub））要谨慎：插件和服务同进程、权限相同，只装信得过的。
- 点开一个已装的插件看详情（只有管理员能看）：
  - **「这个插件会」**（This plugin can）：它声明要用的能力，比如以授权的账号跑 Claude、在自己的隔离沙箱里跑 Claude、在服务器上拉起外部程序、访问外部网络服务、按时间表在后台运行。只是说明，不是开关；装之前先看一眼。
  - 子进程：运行状态、健康检查（**「健康」**（Healthy）/ **「不健康」**（Unhealthy）），掉线会自动重启，点开看它的输出。
  - **「定时任务」**（Routines）：插件自己的时间表，写着下次、上次什么时候跑、成没成功。
  - **「用量」**（Usage）：插件用 Claude 时，今天和累计跑了几轮、花了多少。插件在自己的沙箱里跑 Claude 用的是这台服务器的 Claude 登录和额度，不记在哪个成员账号上；插件可以给自己设每天的上限，到了就停。
  - **「插件日志」**（Plugin log）：插件自己记的日志，可以只看警告和错误。插件出问题时先看这里。
  - 沙箱里的 Claude 没有命令行，只能读写插件给它的那个目录；插件也可以让它只读查阅服务器上指定的资料目录（写不了）。
- **插件能改到的地方**（装之前在「这个插件会」里看清楚）：订阅对话开始和结束、工具调用、登录这些事件；在 Claude 执行命令前拦下危险操作、自动批准放心的命令、在消息发给 Claude 前改写、按项目定模型和推理强度；给 Claude 和 dimensio 加工具（结果可以画成卡片）、提供模型（出现在 Claude 的模型菜单和 dimensio 的「模型服务」里，插件设置里勾选给哪些 agent、成员能不能用）；接管某个内置功能（插件关掉或起不来会自动换回内置的）；提供通知渠道（比如飞书、Telegram）和登录页上的外部登录按钮（只能登进已有的账号，不会自动建号）。界面上插件可以加主页卡片、Claude 工作台的标签、输入框「/」命令和「＋」菜单项、消息和会话菜单里的操作。能拦命令、改消息的插件权力很大，只装信得过的。
- 有的开关改完要重启才生效，页面顶部会出现 **「有改动等重启生效」**（Changes take effect after a restart），可以选空闲时重启。

### 插件市场：更新只提示，不自动装

- 服务器启动 1 分钟后查一次市场，之后每 6 小时查一次；打开「功能扩展」时也会顺手刷新（标题旁的 **「检查更新」**（Check for updates）手动查）。
- 有新版本时，「功能扩展」页顶上出现一块 **「{n} 个插件有更新」**（{n} plugin updates），写着 **「只提示，不会自动装」**（Nothing installs automatically）；设置里的「扩展」那一行和「功能扩展」标签上也会出个数字角标。点 **「更新」**（Update）才会装，不点就一直用现在的版本。
- 装完不满意：插件详情里能 **「回退」**（Roll back）到上一版，或在 **「插件市场里的版本」**（Versions in the plugin market）里挑一个指定版本装；内置功能换上了市场版的，还能 **「恢复内置版」**（Restore built-in version）。市场版起不来时会自动退回内置版。有的要重启才生效，页面会提示。
- 只有管理员能装、能更新。
- **在 Muse 上**：市场的索引和插件包都放在 GitHub 的发布页上，服务器在后台去取，要先放行 `github.com` 和 `release-assets.githubusercontent.com`（让 Muse 跑 `allow-sites github.com release-assets.githubusercontent.com`，用户在 Muse 里批审核卡，选项见 `../MUSE.md` 2.0；新装时安装脚本已经一起弹过这两张卡）。页面上出现「插件市场没拉下来：…」多半就是审核卡没人批。

## 常见问题

- **装了技能，注册账号的 Claude 里用不了**：多半装在「我自用」里了——切到 **「全服统一」** 再装（或在那一栏里添加），成员的 Claude 才会加载。
- **装了没反应**：Claude 要从下一条消息起才加载；dimensio 要开新对话；还要确认详情里「生效 Agent」勾上了这个 agent、开关是开着的、需要填的凭据填好了。
- **连接器显示「需要登录」、Claude 说连不上**：这个连接器要 OAuth 授权，在扩展页它的控制面板点「连接」，或在对话里点「授权」（见上面「远程连接器授权」）。授权页跳回后一直转圈，多半是 Muse 里有对方网站的审核卡没批。报「平台（Muse）不允许在这里登录这个服务」（`refresh_rejected`）的，是被拦的那几家（Figma、Stripe、Zapier），别再重试，按上面「在 Muse 上不能用 OAuth 登录的几家」走替代办法。显示「需要配置 OAuth 应用」的，见「要自备 OAuth 应用的连接器」。
- **dimensio 用不了插件**：插件只支持 Claude Code；插件里的技能想给 dimensio 用，可以在「技能」里单独添加。
- **「发现」里拉不出东西 / 添加插件失败**：多半是 github.com 的审核卡没批，见上面。
- **要浏览器的插件 / 连接器**（Playwright、Chrome 操控、网页截图这类）：在 Muse 上装了也用不了，这台 VM 起不了浏览器（见 08-faq.md）。联网搜索、抓网页文字不需要装东西，本来就能用。
