# 定时触发（Routines）

定时触发让 Claude（或 Gemini）按计划无人值守地执行一段指令；Claude 的每次运行就是一条普通会话，跑的时候能点进去看、跑完随时回看。这是核心功能，每个账号各有自己的一份定时任务。

## 定时触发是什么

定时触发（界面上叫「定时任务」，侧栏入口叫「定时触发」，英文 Routines）是按计划自动执行的一段提示词：到点后服务端自己替你发起一轮对话，没有任何客户端在线也照样跑。

- Claude 引擎的一次运行 = 服务端替任务主人发起的一条普通 Claude 会话（和你在 Claude 页里开的会话走同一条路）：会话列表里实时出现、带「在跑」呼吸点，点进去能看直播、能按停止；会话标「定时任务」来源。
- 运行在任务主人自己的身份和权限里：管理员的任务能动整台机器；成员的任务和他平时聊天一样，只能在自己的文件夹里活动，没有命令行权限的成员在定时任务里也没有。
- 系统提示末尾会告诉模型「这是无人值守的定时任务，别停下来提问」。但如果权限模式要求批准（手动 / 接受编辑），遇到需要批准的操作它会停下来等你——会话亮「待回答」，定时任务页显示「等你处理」，你批了它接着跑。想全程自己跑完，权限选「自动」。
- 适合：每天早上汇总新提交、每小时检查某个目录或网页、每周出一份报告、在某个仓库里定期跑检查。不适合要求精确到秒的任务。

## 定时触发的界面入口

- 手机：进 Claude 分页 → 左上角打开历史抽屉 → 「定时触发」。整页打开，左上「‹」返回。
- 电脑：Claude 分页左侧栏的「定时触发」。页面铺在右边正文区，侧栏照旧可点；点侧栏里的会话或「新对话」，这一页自动让开；右上「×」也能关。
- 管理员另有入口：设置 › Claude › 扩展与记忆 › 「定时任务」。
- 系统返回键逐级退：先关下拉菜单 → 关编辑表单（有未保存修改会先问「放弃没保存的修改？」）→ 从详情回列表 → 关整页。

接口：`routines.list`、`ui.open`

## 定时任务列表页

列表页标题「定时任务」，下面是一行说明横幅（任务在服务器上运行，服务器在线就会按时跑）。

- 任务以卡片排列（宽屏两列、手机一列）。卡片上：名称；描述（没写描述就显示指令开头，最多三行）；底部一行「启用中 / 已暂停 / 已完成 · 频率」，右侧是工作文件夹名（Gemini 任务显示 Gemini）。
- 正在跑的卡片右上角显示「运行中」，停在审批上等你的显示「等你处理」，上次失败的显示「上次失败」。
- 卡片右上角「⋮」（电脑上悬停才出现）：立即运行 / 暂停或启用 / 编辑 / 复制 / 删除。点卡片其它地方进详情。
- 页头右侧：搜索（按名称和描述）、筛选（频率：全部 / 循环 / 一次性 / 仅手动；状态：全部 / 启用中 / 已暂停）、排序（下次运行 / 名称 / 最近运行，另有「显示已完成」开关——跑完了的一次性任务默认隐藏）、「新建任务」。
- 「新建任务」是个下拉：「让 Claude 帮我建」（开一个新对话、输入框预填「帮我建一个定时任务：」，你说想做什么，Claude 用 `routines.create` 替你建）或「手动设置」（打开表单）。

## 定时任务详情页

顶栏：返回、任务名、编辑（铅笔）、删除（垃圾桶）、「⋮」（复制 / 打开最近一次的会话）、「立即运行」。正文宽屏左右两列：

- 左列：描述；状态（启用开关 + 徽标 + 「下次运行：明天 09:00」，服务器停机错过的那次显示「错过了 …」）；文件夹（工作文件夹，开了 worktree 再加一枚「每次从 X 切 worktree」）；重复（频率 + 服务器时区）；模型（引擎 · 模型 · 思考强度 · Fast）；权限；会话方式（接着上次的会话时有「打开那个会话」）；通知。
- 右列：指令（长了折叠，「显示全部」展开）；运行记录。
- 运行记录：每次一行，图标表示结果（✓ 成功、✕ 失败、转圈 运行中、空心圈 跳过 / 中断、橙点 等你处理），后面是时间、「手动」标记（立即运行触发的）、结果摘要、耗时；点一行打开那次的会话。最多保留最近 30 次。
- 正在跑时顶部有横幅：「正在运行。打开会话」；停在审批上时是「这次运行停在一个需要你批准或回答的地方。去处理」。

## 新建与编辑定时任务

新建是整页表单；电脑上编辑是盖在详情页上的对话框，手机上编辑也是整页。底部「取消」与「创建」/「保存」；保存按钮灰着时悬停能看到原因（填一个名称 / 写上指令 / 频率写法不对 / 一次性运行要选一个以后的时间）。

1. 「名称」必填；「描述」可选（显示在卡片上）。
2. 「指令」：每次运行发给模型的完整提示词。框里底部一行：左边是权限药丸，右边是模型药丸（模型 · 思考强度 · Fast）。
3. 指令框下面的位置条（Claude 引擎才有）：
   - 工作文件夹：默认工作空间、你的 Claude 项目、或「选择其他文件夹…」（电脑客户端弹系统选目录框，网页 / 手机用工作空间选择器把文件夹拖进底栏）。任务就在这个文件夹里跑，会话也归到对应项目下。
   - 分支 + Worktree 开关：文件夹是 git 仓库时才可用。打开 Worktree = 每次运行先从仓库切一个新分支和独立工作目录（`.claude/worktrees/` 下）再干活，你手上的检出不受影响；分支药丸选从哪个分支切（默认当前分支）。换文件夹会清空分支并关掉 Worktree。
4. 权限：设置默认（跟设置 › Claude 的默认权限模式）/ 手动 / 接受编辑 / 计划 / 自动 / 绕过权限（后两个视身份与主机设置）。手动和接受编辑在无人值守时会停下来等你。
5. 「频率」分段条：手动 / 一次 / 每小时 / 每天 / 工作日 / 每周 / 自定义，详见下一节。下面实时显示「下次运行：…」。
6. 「运行」卡：引擎（Claude / Gemini，Gemini 扩展装了才有）；会话方式（每次新会话 / 接着上次——接着上次 = 每次在同一个会话里往下聊，模型记得上回做过什么；换了文件夹或 Worktree 开关会重新开）；Gemini 引擎是「联网搜索」开关；「跑完通知我」。
7. 新建的任务默认启用；在详情页的状态开关或卡片菜单里暂停 / 启用。

接口：`routines.create`、`routines.update`

## 定时触发的引擎与模型

定时任务可选两种引擎，模型与思考强度从服务端能力表现取：{{models}}

- Claude（默认）：和 Claude 页的会话完全一样的工具、扩展、项目与权限规则。结果是一条 Claude 会话。
- Gemini：属于 Gemini · Vertex 功能扩展，没装或对这个账号没开时不出现。单轮问答（可联网搜索），不碰文件，结果存进 Gemini 的对话历史；没有工作文件夹、权限、会话方式这些设置。
- 思考强度：Claude 不允许选 Ultracode（无人值守跑动态工作流、成本不可控），保存会被拒。
- 引擎对账号的可用性每次运行时重新判断：创建后管理员关掉了这个 agent，到点不运行，运行记录写明原因。

## 定时触发的频率与时区

| 频率 | 需要设置 | 卡片上的显示 |
|---|---|---|
| 手动 | 无 | 仅手动运行（只在点「立即运行」时跑） |
| 一次 | 日期和时间 | 一次 · 明天 09:00（跑完后状态变「已完成」，默认从列表隐藏） |
| 每小时 | 第几分钟 | 每小时 · 第 5 分 |
| 每天 | 时间 | 每天 09:00 |
| 工作日 | 时间 | 工作日 09:00（周一到周五，不识别法定节假日） |
| 每周 | 星期（可多选）+ 时间 | 每周一、三 09:00；选了六日显示「周末」 |
| 自定义 | cron 表达式 | 常见写法会翻成人话（工作日 / 周末 / 每 N 小时 / 每月 N 日），其余显示「自定义 · 表达式」 |

- 自定义 cron 规则（与官方 Claude 桌面端一致）：5 段「分 时 日 月 周」，只认数字（周日写 0，不收 7，不认 MON / JAN），支持 `*`、`,`、`a-b`、`*/n`；最多每小时一次（分钟段只能写一个数字）。日和周都受限时按标准 cron 取并集。
- 时间按服务端所在机器的本地时区计算，表单与详情页标着服务器时区（例如 GMT-5）。
- 调度精度约 30 秒；改频率或重新启用时，下次运行时间从当前时刻重新算。

## 立即运行、暂停、复制与删除

- 「立即运行」：不等计划时间马上跑一次，不影响下次计划时间；正在跑时按钮置灰。同样计入额度，额度用完直接提示原因。
- 暂停 / 启用：暂停后不再自动触发；启用从当前时刻算下一次。成员启用中的任务数有上限，到上限时启用会被拒。
- 复制：设置全带上、名字加「副本」，默认暂停，运行记录不带。
- 删除：确认框「删除「名称」？已经跑出来的会话会保留。」

接口：`routines.run`、`routines.update`、`routines.delete`

## 定时任务的结果去哪看

- 详情页的运行记录（最近 30 次：时间、触发方式、结果、摘要、耗时、会话）。
- Claude 引擎的每次运行都是 Claude 页会话列表里的一条会话（标「定时任务」来源）；开了 Worktree 的会话在那个 worktree 里。Gemini 引擎的结果在 Vertex 分页 Gemini 对话的历史里。
- 「跑完通知我」：每次运行结束，打开着的 bridge 页面会提醒（页面在后台时是系统通知，跟设置里「任务完成」那类通知开关走；在前台是页内提示）。
- 管理员可在服务端控制台的「定时任务」页按用户只读查看每个人的任务；被查看的成员会收到访问记录。

接口：`routines.list`、`sessions.list`、`sessions.read`

## 定时触发的限制与规则

- 宕机不补跑：服务端停机、睡眠期间错过的计划，开机后不补跑，直接跳到下一次，并在卡片 / 详情标「错过了 …」。服务重启时正在跑的那次在运行记录里记为「已中断」（会话本身可能由重启续跑接着做完）。
- 只有常驻的正式服务端会调度：本机调试实例不会触发定时任务。
- 不重叠：同一条任务上一次还没跑完，到点这次记为「已跳过」。「接着上次」的任务撞上那个会话正被你用着，也跳过、不打断。
- 并发与额度：Claude 引擎的运行和聊天共用同一套并发上限与额度（成员每次运行算一轮）；满了这次记失败并写明原因。管理员不限额度。
- 账号停用后，该账号的定时任务不再运行。工作文件夹被删或不再有权限时，运行记录写明「工作文件夹不可用」。

## 用接口管理定时任务

外部 agent 可以经接口完成与界面相同的操作，作用范围是调用身份自己的定时任务。

- 查看：`routines.list` 返回全部任务（含工作文件夹、worktree、权限模式、会话方式、最近 5 次运行）和正在运行的任务 id。
- 新建：`routines.create`，必填指令与频率；频率可用 daily / weekdays / weekly（days 数组）/ hourly / once（at 毫秒时间戳）/ manual / cron；可选 cwd（工作文件夹绝对路径）、worktree、branch、permissionMode、fast、sessionMode（new / continue）、notify、description、引擎与模型。
- 修改：`routines.update`，只传要改的字段；改频率或启用状态会重算下次运行时间。
- 立即运行：`routines.run`，异步，立刻返回；之后用 `routines.list` 看状态，用 `sessions.read` 读结果会话。
- 删除：`routines.delete`。
- 建议：替用户建任务前先确认频率与时间（服务端时区）和要在哪个文件夹里跑；指令里写清输出放哪个文件或以什么格式总结；想让它全程自己跑完，permissionMode 用 auto。
