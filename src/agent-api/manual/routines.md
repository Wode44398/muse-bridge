# 定时触发（Routines）

定时触发让 Claude（或 Gemini）按固定频率无人值守地执行一段指令，结果存成一条会话事后回看；这是核心功能，每个账号各有自己的一份定时任务。

## 定时触发是什么

定时触发（界面上也叫「定时任务」「路由」，英文 Routines）是按计划自动执行的一段提示词：到点后服务端自己开一轮新对话把指令发出去，没有任何客户端在线也照样跑。

- 每次运行都是一条全新的会话，不接续上一次的上下文。需要「接着上次做」时，让指令自己去读上次留下的文件。
- 运行在任务主人自己的身份和权限里：管理员的任务能动整台机器；成员的任务和他平时聊天一样，只能在自己的文件夹里活动，没有命令行权限的成员在定时任务里也没有。
- 无人值守：模型提问会被自动拒绝并要求它按合理默认继续；不能进入「先出计划」模式；需要批准的调用直接放行（Claude 引擎）。所以指令要写成「一次说清、可自主完成」的形式。
- 适合：每天早上汇总新闻/笔记、每小时检查某个目录或网页、每周生成报告。不适合：需要人中途确认的操作、要求精确到秒的任务。

## 定时触发的界面入口

定时触发是一个全屏页面，标题「Routines」，左上角带一枚钟形图标。

- 手机：进 Claude 分页 → 点左上角打开历史抽屉 → 抽屉顶部「定时触发」（与「新对话」「搜索」「新建项目」「新建临时对话」同一组）。
- 桌面：Claude 分页左侧栏顶部同一个「定时触发」按钮。
- 管理员另有入口：设置 › Claude › 扩展与记忆 › 「定时任务」（手机设置是推入页，桌面设置是一行），点了跳到同一页面。成员的设置里没有这一入口，只能走历史抽屉。
- 页面返回：左上「‹」；系统返回键逐级退（先关引擎菜单，再从编辑表单回列表，再关整页）。

接口：`routines.list`、`ui.open`

## 定时触发的列表页

列表页列出当前账号的全部定时任务，每行一张卡片。

- 卡片主体显示：名称（未填为「未命名路由」）；第二行是「频率 · 引擎 · 模型」，后面跟状态——正在跑显示「运行中…」，否则显示上次结果（中文界面原样拼成「上次ok」「上次error」「上次running」）。
- 若服务端在计划时刻没在运行（关机、睡眠、重启），卡片多一行「已错过 HH:MM 那次（服务端当时没在运行）」；跨天会带日期。之后正常运行一次后这行消失。
- 卡片右侧三个控件：▶「立即运行」（运行中时置灰）、开关「启用」、垃圾桶「删除」。
- 点卡片主体进入编辑表单。右上「＋ 新建」新建。
- 空列表提示「还没有定时路由。点右上角「＋ 新建」。」；连不上服务端时顶部提示「加载失败：连不上电脑（列表可能不是最新）」。

## 新建与编辑定时任务

新建/编辑表单标题为「Routines / 新建路由」或「Routines / 编辑路由」，底部「取消」与「创建」/「保存」。

1. 「名称」：最长 120 字，可留空（保存为「未命名路由」）。
2. 「指令 Instructions」：必填，每次运行发给模型的完整提示词。空着时「创建」按钮不可点，强行保存提示「请填写指令（Instructions）」。
3. 指令框下方的引擎按钮（显示为「Claude · 模型名 · 思考强度」）：点开选「引擎」「模型」「思考强度」，Gemini 引擎还多一项「联网搜索」开/关。不选模型和强度 = 用服务端默认。
4. 「频率」：每天 / 每工作日 / 每周 / 每小时，详见下一节。
5. 「启用」开关：关着保存 = 存下但不自动触发（仍可手动「立即运行」）。

保存失败会在表单底部显示「保存失败：原因」，常见原因见「定时触发的限制」。

接口：`routines.create`、`routines.update`

## 定时触发的引擎与模型

定时任务可选两种引擎，模型与思考强度从服务端能力表现取：{{models}}

- Claude（默认）：与 Claude 分页同一套工具和扩展（技能、插件、连接器、媒体生成工具都在），能读写文件、跑命令（视身份）、联网。结果是一条 Claude 会话。
- Gemini：属于 Gemini · Vertex 功能扩展，扩展没装或 Gemini 对这个账号没开时，引擎菜单里没有这一项。Gemini 引擎是单轮问答（可开联网搜索），不会操作文件；结果存进 Gemini 的对话历史，联网时末尾附「来源」列表。
- 思考强度：Claude 不允许选 Ultracode（无人值守跑动态工作流、成本不可控），选了保存会被拒，需改选 Extra 或 Max。Gemini 的部分模型不支持 Minimal，菜单里会自动隐藏。
- 引擎对账号的可用性在每次运行时重新判断：创建后管理员关掉了这个 agent，到点不会运行，上次结果记为失败并写明「未启用或没有权限，这次没有运行」。

## 定时触发的频率与时区

频率是四种预设之一，不支持 cron 表达式，也不支持「每 N 分钟」。

| 频率 | 界面 | 需要设置 | 卡片上的显示 |
|---|---|---|---|
| 每天 | 「每天」 | 时间（时:分） | 每天 09:00 |
| 每工作日 | 「每工作日」 | 时间 | 每工作日 09:00（周一到周五，不识别法定节假日） |
| 每周 | 「每周」 | 星期几 + 时间 | 每周一 09:00 |
| 每小时 | 「每小时」 | 第几分钟（0–59） | 每小时 · 第 5 分 |

- 时间按服务端所在机器的本地时区计算，表单上标注「服务器时区 GMT+8」。
- 新建默认：每天 09:00；每周默认周一。
- 调度精度约 30 秒：到点后半分钟内开跑。
- 改频率或重新启用时，下次运行时间从当前时刻重新算。

## 立即运行、启停、编辑与删除

列表卡片上的控件都即时生效。

- 「立即运行」：不等计划时间，马上跑一次；不影响下次计划时间。同一条正在跑时不会重复开跑。立即运行同样计入额度，额度用完会直接提示原因。
- 「启用」开关：关掉后不再自动触发，下次运行时间清空；重新打开从当前时刻算下一次。成员启用中的任务数有上限（管理员在控制台设置），到上限时打开会被拒。
- 编辑：点卡片进表单，改完「保存」。可以改名称、指令、引擎、模型、强度、联网、频率、启用。
- 删除：垃圾桶 → 确认框「删除这条路由？」→ 确定。删除不影响已经产生的历史会话。
- 操作失败（如断网）界面会回滚并在顶部提示「切换失败 / 运行失败 / 删除失败：连不上电脑，请重试」。

接口：`routines.run`、`routines.update`、`routines.delete`

## 定时任务的结果去哪看

每次运行的结果有两处可看。

- 卡片状态：列表上「上次ok / 上次error」；服务端还为每条记录保留上次运行时间、上次会话 id 与结果前 200 字的摘要（经接口可取）。
- 完整过程：Claude 引擎的结果是一条新会话，出现在 Claude 分页的会话列表里，可以像普通会话一样打开、继续对话；Gemini 引擎的结果在 Vertex 分页 Gemini 对话的历史里。
- 运行中模型被自动切换（安全栅门、回退模型）或账号池自动换号时，结果摘要以「⚠」开头写明发生了什么。
- 管理员可在服务端控制台的「定时任务」页按用户只读查看每个人的任务（名称、频率、下次/上次、状态、提示词）；被查看的成员会收到「查看了你的定时任务内容」的访问记录。

接口：`routines.list`、`sessions.list`、`sessions.read`

## 定时触发的限制与规则

- 宕机不补跑：服务端停机、睡眠期间错过的计划，开机后不会补跑，直接跳到下一次，并在卡片上标「已错过」。
- 只有常驻的正式服务端会调度：本机调试实例不会触发定时任务。
- 不重叠：同一条任务上一次还没跑完，到点不会再开一次。
- 后台任务：Claude 在定时任务里起的后台子任务/后台命令会被等待完成后才收尾（后台命令有时长封顶，长时间无进展会被结束）。
- 额度：成员的每次运行（含立即运行）算一轮聊天额度，额度用完则这次不跑，上次结果记为失败并写明原因；管理员不限。
- 成员上限：每人启用中的定时任务有数量上限，超出提示「每人最多 N 条启用中的定时任务。先停用或删掉一条再加。」
- 账号停用后，该账号的定时任务不再运行。
- 指令为空不能保存；名称超过 120 字会被截断。

## 用接口管理定时任务

外部 agent 可以经接口完成与界面相同的操作，作用范围是调用身份自己的定时任务。

- 查看：`routines.list` 返回全部任务和当前正在运行的任务 id。
- 新建：`routines.create`，必填指令；频率用四种预设之一（每天/每工作日/每周/每小时，配时、分、星期）；可选引擎 Claude 或 Gemini、模型、思考强度、联网（仅 Gemini）、是否启用。
- 修改：`routines.update`，只传要改的字段；改频率或启用状态会重算下次运行时间。
- 立即运行：`routines.run`，异步，立刻返回；之后用 `routines.list` 看状态，用 `sessions.read` 读结果会话。
- 删除：`routines.delete`。
- 建议：替用户建任务前先确认频率与时间（服务端时区），指令里写清输出要放在哪个文件或以什么格式总结。
