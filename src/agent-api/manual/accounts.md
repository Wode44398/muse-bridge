# 账号与管理

本章讲谁能登录 bridge、怎么登录和注册、账号分几档、注册用户的额度怎么算、管理员在服务端控制台能做什么、Claude 订阅号池与自动换号、成员给管理员的可见性授权、扩展中心，以及反馈的去向。

## 身份种类

bridge 的使用者分管理员和注册用户两类，另有几种不用登录的受限身份。

| 身份 | 怎么来 | 能做什么 |
|---|---|---|
| 管理员 | 服务器主人，用访问令牌登录（或用已登录的管理员手机扫码） | 全部功能，不受额度限制，能进服务端控制台、扩展中心、号池 |
| 注册用户 · 完全信任 | 管理员确认后发的完全信任邀请码注册，或管理员升档 | 有命令行、终端和浏览器，权限等同管理员（见「档位」） |
| 注册用户 · 普通 | 普通邀请码注册，或管理员直接建账号 | Claude 只能在自己的目录里读写，没有命令行 |
| 服务账号 | 管理员建或标记，给程序用（例如 QQ 机器人） | 服务器关掉多用户后仍能登录；不吃默认额度 |
| 访客 | 打开别人分享的链接、聊天快照链接 | 只能用那条链接给的范围，没有设备、设置、反馈等账号能力 |

- 注册用户只有在服务器开着「给别人用」（多用户）时才能登录和注册；关着时只有管理员和服务账号能登录，普通账号登录会被拒（「这台主机只接受访问令牌登录」）。
- 每个注册用户有自己的工作空间目录、会话和设置；能用哪些 agent 由管理员按人勾选（新账号默认 Claude 和 Gemini；ChatGPT · Codex 只给管理员）。

接口：`whoami`

## 登录方式

bridge 支持三种登录方式，入口都在 设置 › 账户（没登录时账户区就是登录页）或首屏登录卡。

- 账号密码：注册用户用登录名（或账号 id）+ 密码登录。同一账号 5 分钟内错 6 次锁 5 分钟；同一来源 IP 15 分钟内错 20 次锁 15 分钟。
- 访问令牌：「用访问令牌登录」，粘贴服务端的访问令牌，以管理员身份登录。登录后浏览器/设备里存的是一张单独发给这台设备的「管理员登录」，不是令牌本身；管理员可在控制台逐台吊销，重新生成访问令牌会让全部管理员登录作废。
- 扫码登录：电脑浏览器登录页点「扫码登录」出二维码，已登录的手机 app 在 设置 › 账户 ›「扫一扫 · 登录网页版」扫码并确认，网页即以手机当前的身份登录。码 3 分钟有效，确认后 60 秒内不领取作废。
- 另有「扫码连接」：已登录的一方出示配对码，未登录的手机 app 扫码换连那台服务器并以出码人身份登录（见「安卓 app」章）。
- 「退出登录」只退出当前这台设备；「切换账号」= 先退出再用别的账号登录。注册用户可在 设置 › 账户 ›「修改密码」，改完别的设备要重新登录，这台不受影响。
- 设备（桌面客户端登记的电脑）跟着登录走：退出或登录失效后设备随之失效，重新登录会自动重新登记。

## 邀请码注册

注册用户凭一次性邀请码自助注册，注册即登录。

- 入口：登录页「注册新账号」：填账号（2–32 位字母、数字、下划线、连字符，不能以 _ 或 - 开头）、密码（至少 8 位）、确认密码、邀请码。服务器关闭注册时不显示这个入口。
- 邀请码由管理员在控制台「用户」页生成：「＋ 普通邀请码」或「＋ 完全信任邀请码」（后者要先确认「等同管理员」的说明）。新码 7 天内有效、只能用一次，没用的可「作废」。升级前发的老完全信任码不过期，控制台会提示作废。
- 注册界面会告知：服主默认只看得到你的会话标题、时间和用量；看内容要你在设置里允许。
- 注册接口按来源 IP 限流，防邀请码爆破。
- 管理员也可以跳过邀请码直接「＋ 新建账号」或「＋ 新建服务账号」。

## 档位：普通与完全信任

档位决定注册用户能不能碰服务器本身。

- 普通（无命令行）：Claude 只能在他自己的目录里读写、联网和调用工具，看不到别人的对话和文件；权限模式只能选手动、接受编辑、计划。可以放心发。
- 完全信任（有命令行）：有命令行、终端和浏览器，跑在服务端同一个系统账户下，能读到服务器上所有人的对话、文件和全部凭据（号池令牌、各家 API Key），等同管理员。只给完全信任的人。
- 升档：控制台「用户」› 某人「管理」›「升为完全信任（给命令行）」，要勾确认。降档「降为普通（收回命令行）」立即生效：他正在跑的对话中止，侧栏终端和浏览器关掉，账号、对话、文件都保留。
- 改名为「完全信任」之前开的老 Pro 档账号不会自动降级，控制台列在「待确认的完全信任账号」里逐个确认或降级。
- 服务器目前只做逻辑隔离；进程隔离、容器隔离尚未接入。

## 额度：注册用户受哪些限制

额度只约束注册用户（服务账号除外），管理员自己和管理员代发的轮不受限。

| 维度 | 含义 |
|---|---|
| 每天最多几轮 / 最近 7 天最多几轮 | Claude 对话、Gemini 对话、定时任务都算一轮；开跑时就记，并行发也绕不过去 |
| 每天最多花多少 / 最近 7 天最多花多少 | 美元，按 API 价估算（每轮结束时 Claude 报的金额，取这一轮新增部分）；共用订阅号池时反映用量，不是真花出去的钱 |
| 每天最多生成几次图片、语音、音乐 | 媒体页与 Claude 的媒体工具合计 |
| 每天最多生成几条视频 | 视频单次花费最高 |
| 每人同时最多几轮 / 全服同时最多几轮（注册用户合计） | 并发上限 |
| 每人最多几条启用中的定时任务 | 定时任务无人值守，防止挂一串自动烧额度的轮 |

- 「每天」在策略时区（默认北京时间）0 点换日；「最近 7 天」是滑动窗口，最早那天滑出后逐步恢复。
- 成员能用的高消耗功能（管理员可逐项对成员开关）：快速模式（fast）、常驻动态工作流（关着时降档）、1M 上下文（关着时到 20 万 token 自动压缩）、生成图片 / 语音 / 音乐、生成视频。关掉的功能，成员界面上按钮还在，但发出去按关着处理。
- 新部署默认用推荐值（有上限、高消耗功能对成员关闭）；升级前已有账号的老部署保持原来的不限额行为。管理员可一键「改用推荐值」。
- 超额时这一轮不开跑，提示「今天的额度用完了」/「这 7 天的额度用完了」及恢复时间，并请联系管理员。
- 个人覆盖：管理员在控制台「用户」› 某人「调整额度」单独设，空着 = 跟默认，填 0 = 对他不限。
- 成员查看自己：设置 › 账户 ›「我的额度」（今天、最近 7 天，设了上限的按次项显示「已用 / 上限」，未开放的显示「未开放」）。
- 聊天快照访客的轮记在铸这个快照的账号头上，高消耗功能也跟他走。

接口：`usage`

## Claude 订阅额度（5 小时 / 每周）

除了 bridge 自己的额度，Claude 订阅账号本身有官方的 5 小时与每周用量窗口，bridge 把它显示出来。

- 设置 › 账户 › 用量：「当前会话（5 小时）」「本周」（桌面为「订阅额度」：5 小时额度、本周额度）的已用百分比与重置时间。
- Claude 输入框里的上下文用量环（「查看用量」）点开，弹层下半部分列出各额度桶（「5 小时上限」「每周 · 所有模型」等）。
- 撞上 5 小时限额时，开着「限额重置后自动继续」（设置 › Claude ›「撞上限额时」，每人自己设）会在额度恢复后自动接着跑完这一轮。
- 管理员另可看号池里每个账号各自的用量（见下节）。

## Claude 号池与自动换号

号池是管理员登记的一组 Claude 订阅账号，所有人的 Claude 对话都从号池里当前在用的那个号出额度。只有管理员能管理。

- 入口：设置 › Claude ›「订阅号池」，或服务端控制台「Claude 账号」页。
- 添加：「添加账号」，填名称（如「主号 / 备用号」）和 token——在目标账号登录状态下运行 `claude setup-token`，把返回的长期 token 粘进来；token 留空 = 用服务器本机已登录的凭证。可编辑、调整顺序（上移 / 下移）、删除（删的是当前号会自动切到另一个）。
- 每个号显示套餐（Max / Pro）、「使用中」/「待用」、5 小时 / 每周 / Fable 额度（控制台还有 Opus、Sonnet 周额度）及「快满了 / 已满」提醒；闲置的号显示上次使用时的数据。
- 切号：「切到此号」即时全局生效——管理员对话、成员会话、定时任务的下一次生成都用新号（正在跑的那一轮不受影响）。各号共享会话记录，切号后同一条对话可以接着聊。
- 自动换号（智能路由，默认关）：「额度用尽自动换号」——当前号某项额度用满或 token 失效时，自动换到号池里还有余量的号；开跑前已知用满就探测其余各号余量再选；跑到一半撞墙，给该号记冷却到重置时刻并换号，新版 app 会自动用新号重发这条消息。号池至少要两个账号才用得上。
  - 「额度恢复后回到首选号」：开着 = 每轮都用列表里最靠前的可用号（主号一恢复就切回）；关着 = 用满再换（当前号能用就一直用它）。
  - 「会话中无缝换号」：当前号快用满（98%）或撞墙时，在两步之间换到下一个号接着跑，对话不中断、不用重发。
  - 开着时显示「最近的自动切换」记录（从哪个号到哪个号、原因、时间）。
- 管理员还可在 设置 › Claude ›「模型服务」›「自定义 API」接入第三方模型服务（模型见 {{models}}）。

## 管理员可见性（成员授权）

成员自己决定管理员能看到他的什么；默认管理员只看得到元数据。

- 默认：管理员在控制台只看得到成员的会话标题与时间、定时任务的名字与时间、用量、在线状态。
- 三个开关，在成员自己的 设置 › 账户 ›「管理员可见性」：
  - 「允许查看对话内容」：Claude 与 Gemini 的对话正文、生成的媒体、定时任务的提示词和结果。
  - 「允许代聊与代答」：管理员可以在他的空间里代他发消息、替他回答提问和审批；代发的消息开头标着「【管理员代发】」。接着聊他自己已有的会话还要同时允许查看对话内容（从头到尾都是管理员代发的会话除外）。
  - 「允许查看我的电脑」：管理员可以对他登记的电脑截屏、读取系统信息或派发操作。
- 每次管理员查看或代操作，成员那边当场弹提示，并记进「管理员的访问记录」（一分钟内同一操作合并成一条）。
- 服务账号没有真人表态，默认三项全开。管理员自己的数据不经过这层。
- 这层约束的是控制台的默认行为，不是系统级隔离：服主管理着服务器，技术上仍能读到服务器上的文件（设置页如实说明）。
- 只有注册用户有这一组；管理员自己看不到。

## 服务端控制台：总览与用户

服务端控制台是管理员管理整台服务器的页面，左侧分页：总览、活跃进程、用户（没开多用户时叫「服务账号」）、额度与注册、会话 / 续聊、定时任务、媒体、Claude 账号、设备、服务控制。

- 入口：设置 › 服务器 ›「服务端控制台」（桌面在 设置 › 连接与更新）。管理员身份默认可远程进入（手机、网页都行）；会把自己关在门外的操作（停服务、停隧道、改开机自启、关掉正在用的公网隧道）远程一律拒绝，只能在那台机器上做。
- 「总览」：主服务、公网访问、开机自启状态，活跃 agent，定时任务运行中，Claude 用量额度（5 小时 / 7 天窗口）。
- 「活跃进程」：所有人正在跑的 Claude / Vertex 对话生成，可中止任意一条（等于那个人自己点「停止」）；长跑媒体生成不在此列。
- 「用户」：
  - 顶部「给别人用」：开放给其他人使用（多用户），开关后重启服务端生效（部署方接管时——服务单元写了 BRIDGE_AUDIENCE_HINT 或 config.json 写了 audienceHint——没有开关，只显示「多用户 / 单人」徽标和部署方给的切换办法，接口也拒绝改动）；附隔离等级说明和「待确认的完全信任账号」。
  - 邀请码：生成普通 / 完全信任邀请码、作废。
  - 账号列表：用量（今天、7 天轮数与美元）、档位、状态；「管理」里可改密码（重置后他所有设备下线）、改登录名（对话、文件、设备、用量不受影响）、升降档、「能用的 agent」按人勾选、「铸聊天快照」授权（能否开公开对话链接）、服务账号标记、「调整额度」、查看「他允许管理员做什么」、停用 / 启用、删除。
  - 停用：立刻登出、在跑的对话中止、登记的电脑断开、发出去的聊天快照关掉；数据保留，重新启用后恢复。
  - 删除：立刻登出、对话中止，他的电脑、端口转发、聊天快照、邀请记录、用量一并删除；数据可选「连对话、文件、媒体一起删（不可恢复）」或「删除并归档」（整个目录挪进归档文件夹）。删掉的账号 id 不再复用。
  - 「管理员登录」：每台用访问令牌或扫码登录过的设备一张，显示来源与最近使用，可单独吊销、「吊销其它设备」或全部吊销。
- 管理员的建删账号、改档位 / 额度 / 授权、号池与策略改动、查看别人的数据、代聊代答都记进管理员侧审计。

## 服务端控制台：额度、会话、定时任务、媒体、设备、服务控制

控制台其余分页覆盖额度策略、代查代聊和服务器运维。

- 「额度与注册」（只在多用户时）：「凭邀请码注册」开关；「注册用户的默认额度」全部维度（见「额度」一节）；「每人同时最多几轮」「每人最多几条启用中的定时任务」「全服同时最多几轮」；「成员能用的高消耗功能」逐项开关；时区；「改用推荐值」。
- 「会话 / 续聊」：按用户浏览会话列表（未授权查看内容的只列标题和时间）、预览、代他续聊或开新会话（要他允许代聊；他那边标「管理员代发」），也能代答他会话里的提问。
- 「定时任务」：按用户看定时任务的频率、状态、上次与下次运行（未授权时不显示提示词）。编辑要到该用户自己的定时任务页。
- 「媒体」：按用户看生成的图片、视频、语音、音乐（需授权查看内容）。
- 「Claude 账号」：号池与智能路由（见上节）。
- 「设备」：全服设备、探查与远程更新、审计、配对卡（见「设备」章）。
- 「服务控制」：运行状态（版本、内存、负载、数据盘剩余、在跑的对话）、「立即重启」或「空闲时重启」（等没有在跑的对话，最多等 30 分钟）、「检查并更新」（源码部署时拉新代码并空闲重启；桌面客户端托管时显示 GitHub 上的新版并提示更新客户端——一键更新在 设置 ›「服务端更新」，agent 用 `server.update_status` / `server.update`；部署方在服务单元里写了 BRIDGE_UPDATE_HINT 的——如 tar 包 + 发布目录部署——照原话显示该怎么更新）、最近日志；「公网访问」（临时地址 / 自己的域名隧道 / 外部反代 / 关闭，可重启隧道、从外网检查）；Windows 主机另有进程控制（启停主服务与隧道、开机自启）。

## 扩展中心：技能、连接器、插件、功能扩展

扩展中心给 agent 加装能力，只有管理员能用；分「我自用」和「全服统一」两个范围。

- 入口：设置 ›「扩展」（手机在「服务器」组；桌面侧栏），或 设置 › Claude ›「扩展与记忆」里的「技能」「连接器」「插件」。
- 每类有「我的」（已装，卡片右上是开关，点进详情看「生效 Agent」、文件、替换、下载、卸载）和「发现」（Anthropic 官方市场与自己添加的 GitHub 市场，「推荐给您」与全部，「+」一键添加；「管理市场…」可「添加 GitHub 市场」）。
- 技能：上传 .md（需含 name 与 description 的 YAML 头）或 .zip / .skill（包内需含 SKILL.md）；对 Claude 下一条消息生效，对 dimensio 与 Codex 在新会话生效。
- 连接器（MCP 服务）：「添加连接器」选本地命令（stdio，填命令、参数、环境变量）或远程 HTTP / 远程 SSE（填地址、请求头）；凭据加密存在服务端，界面只显示打码。Codex 只支持 stdio 连接器；要求 OAuth 登录的远程连接器（Claude 用）添加后在对话里授权：会话信息面板「连接器」卡里状态为「需要登录」的那一行点「授权」，或点输入框上方「连接器需要授权」提示条里的「授权」，在打开的页面登录完会自动连上；授权服务器只接受本机回调时（浏览器跳回后显示打不开页面），把地址栏里的完整地址粘回卡片里提交。令牌存在这个身份自己的 Claude 配置里，之后的会话都能直接用。
- 插件：上传 .zip（包内需含 .claude-plugin/plugin.json），是 Claude Code 专属格式，只对 Claude 生效。
- 同包名的扩展归为一组，可整包启用 / 卸载；每个扩展可勾选对哪些 agent 生效。
- 「功能扩展」页就是 bridge 的插件管理，分「Agent」「功能」「插件市场」「已安装的插件」几区（内置功能逐项开关、改配置，第三方插件的安装与卸载、市场的装 / 更新 / 回退，见「设置」章「扩展」一节和「插件（功能扩展）」章）。下面几条说的是「Agent」区的三个 agent 扩展。
- 「Agent」区：Gemini · Vertex、ChatGPT · Codex、dimensio 三个可选模块，装上才有对应的分页。离线包必须和主程序是同一次打包，所以只装「这一版」的：
  - 一键安装：打包安装的服务端（Windows 桌面客户端里的本机服务端）卡片上有「安装」或「更新到 x」，点了从 GitHub 上和本机同一版本的发版下载离线包（安装包旁边带着离线包时直接用、不下载），核对大小与 sha256 后排进待生效，卡片显示下载进度。
  - 没有按钮时卡片写着原因：源码部署（Linux 脚本、Docker、仓库，扩展随主程序代码内置、跟着主程序更新）；这一版没在 GitHub 公开发布（私有版匿名下不了）；连不上 GitHub（可点「重试」）；这一版的发版里没有这个扩展；更新源被关掉了。这一版不提供、也没装的扩展不列出（公开版没有 ChatGPT · Codex；发行版可在服务单元里用 BRIDGE_MODULES_HIDE 声明不带哪些，如 Muse Bridge 不带 Gemini · Vertex 和 ChatGPT · Codex），Agent 设置页里也不出现。
  - 手动安装：「安装离线包」上传随安装包发的 .zip。
  - 卸载、撤销；装、换、卸都在重启 bridge 后生效（可「立即重启」或空闲时重启）；卡片开关 = 这个 agent 的全服总开关，即时生效。卸载保留它的会话与数据。
  - agent 可用 `modules.list` 看每个扩展能不能装、为什么不能，用 `modules.install` 一键安装（装完要重启服务端，先问用户）。
- 范围：
  - 「我自用」：只进管理员自己的会话（新会话 / 下一条消息生效）。
  - 「全服统一」：给服务器上所有成员加装，成员的 Claude 会话和定时任务都会加载，管理员自己也用得上；和自用那一套互不影响。全服连接器所有成员用同一份凭据，成员看不到凭据。没开多用户时全服扩展只有管理员自己用得上。
- 聊天快照访客的会话不加载任何扩展。

## 反馈去向

反馈是任何登录用户都能提交的问题与建议，统一落在这台服务器上。

- 入口：设置 ›「提交反馈」（手机）/ 设置 ›「反馈」（桌面），可附图片和视频（见「设置」章）。
- 每条反馈存为服务器反馈库里的一篇 markdown（带提交人、界面、版本等元数据和附件），管理员能看到；访客和分享链接不能提交。
- 默认不外发。只有管理员打开了「把用户反馈同时发给 bridge 开发者」，且提交人自己勾了「这条也发给 bridge 开发者」，才会同时发给 bridge 开发者（只带文字、所在界面、版本和系统，不带账号名和服务器地址；图片最多 3 张，视频不发）。发行版可以声明别的去向（比如发成公开 Issue），以界面和 feedback.status 的说法为准。
- 让 Claude 或 dimensio 代报（跟它说「是不是出 bug 了」）去向相同：本机总有一份（frontmatter 带 `via: claude` 或 `via: dimensio`），用户在对话里同意、且管理员开着推送时才发给开发者。
