# 概览

bridge（应用名 The Bridge，当前版本 {{version}}）让用户在手机、网页或桌面客户端上远程驱动服务端上的 AI agent；本章说明它由哪些部分组成、有哪些 agent、谁能用什么、数据放在哪、怎么连上和怎么部署。

## bridge 是什么

bridge 是一个自托管服务：AI agent、文件、会话记录都在服务端那台机器上运行和保存，手机、网页、桌面客户端只是界面。核心 agent 是 Claude（与官方 Claude Code 同源，能读写文件、跑命令、联网、调工具），其余 agent 作为可选的功能扩展装上。

- 典型用法：在手机上给家里电脑或云服务器上的 Claude 派活（写代码、整理文件、做研究、生成媒体），回到电脑前在桌面客户端接着看同一个会话。
- 一台服务端可以只给主人自己用，也可以开多用户给家人朋友用（见「身份与档位」）。
- 回答在服务端跑，界面断网、刷新、关掉都不影响这一轮继续；重新打开会接上进度。
- 源码与开发文档另见仓库；本手册只讲使用。

## 组成部分

bridge 由一个服务端和若干客户端组成，客户端都连同一个服务端。

| 部分 | 是什么 | 说明 |
|---|---|---|
| 服务端 | 跑 agent、存数据的 Node 服务，默认端口 8787 | 装在自己电脑、Linux/Windows 服务器或 Docker 里；自带「服务端控制台」管理页 |
| 网页端 | 浏览器直接打开服务端地址 | 手机浏览器是手机布局，电脑大屏是桌面布局 |
| 安卓 app | 离线壳：界面内置在 app 里、打开即显示，只有数据走网络 | 首次需「扫码连接」或填服务器地址；连不上时可浏览本地缓存；独有「手机操控」（实验性，要无障碍权限） |
| Windows 桌面客户端 | Electron 桌面壳 | 两种角色：①连远端服务器的桌面界面（并把这台电脑登记成「设备」）；②在本机托管一个服务端（安装时选「服务端」，随登录启动） |
| 功能扩展（插件） | bridge 的功能都是插件：Gemini · Vertex、ChatGPT · Codex、dimensio 三个可选 agent 模块，定时任务、设备、内置浏览器等默认开着的内置功能，以及第三方插件 | 基础版只有 Claude；都在 设置 › 服务器 › 扩展 ›「功能扩展」里管：agent 模块安装 / 卸载（打包安装的服务端可从 GitHub 一键安装，装卸后需重启服务端），内置功能逐项开关，官方插件市场装 / 更新插件（见「插件（功能扩展）」章） |

桌面客户端登录后会出现在 设置 › 设备 的「我的设备」里，agent 可以按设备档位远程看屏幕、操作键鼠、跑命令（见「设备」）。

## 有哪些 agent

bridge 的 agent 用统一 id 区分，每个对应主页上的一个入口（分页）。

| id | 名称 | 分页 | 来源 | 能否开给成员 |
|---|---|---|---|---|
| `claude` | Claude | Claude 分页 | 核心自带 | 能 |
| `gemini` | Gemini（Vertex） | Vertex 分页：Gemini 对话、图像、视频、语音、音乐 | 扩展 Gemini · Vertex | 能 |
| `codex` | ChatGPT · Codex | ChatGPT 分页 | 扩展 ChatGPT · Codex | 不能，只给管理员 |
| `dimensio` | dimensio | dimensio 分页（每个成员一个独立实例） | 扩展 dimensio | 能 |

- 某个 agent 能不能用 = 服务端全局开关 ∩ 这个人被授权的名单。管理员在 设置 ›「Agent」分组 › 点某个 agent ›「启用 {名称}」开关它，同页能看能否运行与认证状态；成员的名单由管理员在控制台按人勾选，没勾过的成员默认只有 Claude 和 Gemini。
- 不可用的 agent，界面上根本不出现对应入口。
- 单 agent 模式：一个人能进的分页只剩 Claude 或只剩 dimensio 时，没有主页，打开就是那一页，设置与账户收进侧栏底部的账户行（菜单里有「设置」）。只剩 Gemini 或 Codex 时仍有主页（上面只有那一个入口）。
- 可用模型：{{models}}

接口：`overview`、`whoami`

## 主页与全局入口

主页是多 agent 时的起点，上面是各 agent 的入口（Claude、ChatGPT、dimensio、Vertex，按可用性显示）。

- 手机/网页：主页右上角是账户胶囊——未登录显示「登录」，已登录点开是账户卡：5 小时额度 / 本周额度、「工作空间」、「账户」、「设置」（手机 app 另有「扫一扫 · 登录网页版」）。
- 桌面客户端：主页侧边有「工作空间」和「设置」（Ctrl+K 搜索设置项）。
- 工作空间：服务端文件管理器（浏览、预览、上传、移到回收站等），管理员看整个工作区，成员只看自己的目录。
- 定时任务（Routines）：让 agent 按时间表无人值守跑任务。
- 设置分组（手机/网页）：账户、「Agent」（每个 agent 一页，如 Claude 的全部设置）、「服务器」（扩展、额度与注册、服务端控制台——仅管理员）、「偏好」（通用、外观、壁纸、语言、通知等）、「这台设备」（手机操控、设备）、关于；app 与桌面客户端另有「提交反馈」。桌面客户端的设置是双栏页面，内容相同。

接口：`ui.view`、`ui.open`、`files.list`、`routines.list`

## 身份与档位

bridge 按身份决定一个请求能做什么、数据落在哪。共四类身份，账号又分两档。

| 身份 / 档位 | 怎么来 | 能做什么 |
|---|---|---|
| 主机管理员（服主） | 访问令牌登录，或扫码连接时以管理员身份连上 | 全部功能；工作目录是整个工作区，不设路径边界；管理账号、额度、号池、扩展、公网访问、所有设备 |
| 完全信任成员 | 邀请码注册或管理员新建，档位「完全信任」 | Claude 有命令行。命令行在逻辑隔离下没有可靠边界，等同管理员：技术上能读到服务器上所有人的数据与全部凭据。只该给完全信任的人 |
| 普通成员 | 邀请码注册或管理员新建，档位「普通」 | Claude 能联网、在自己目录里读写改文件，Bash / PowerShell 一律拒绝；数据与其他成员隔离 |
| 分享访客 | 打开公开只读分享链接（`/w/…`） | 只能浏览、下载分享桶里的文件；不能聊天、不能写 |
| 快照访客 | 打开公开聊天快照链接（`/c/…`，目前由 QQ 群机器人生成） | 任何拿到链接的人都能在快照桶里和 Claude 聊（可读写桶内文件，无命令行），只能用 Claude；超过 1 小时没有新消息自动销毁；额度记在铸快照的那个账号上 |

- 多用户默认关闭（「只给我自己」）：此时只有管理员和服务账号能登录。开启后才能注册与邀请。
- 登录方式：账号密码、「扫码登录」（用已登录的手机 app 在账户卡点「扫一扫」）、「用访问令牌登录」（管理员）、「注册新账号」（需邀请码，邀请码默认 7 天过期）。
- 管理员默认只看得到成员的元数据（会话标题、时间、用量、在线状态）。查看对话内容、代他发消息与答审批、查看他的电脑，这三项要成员自己在 设置 › 账户 ›「管理员可见性」里允许，每次访问都记在「管理员的访问记录」。这是控制台的默认行为约束，不是系统级隔离。
- 能否铸公开聊天快照按账号单独授权（控制台用户页），每个账号最多同时 10 个有效快照。

接口：`whoami`、`keys.list`、`keys.revoke`

## 数据放在哪

bridge 的所有数据都在服务端的数据根目录下（默认是程序目录，可单独指定）。

- 工作区：管理员的工作目录，即管理员配置的库目录；管理员身份的 Claude 默认在这里工作，也可以选本机任意目录做项目。
- 成员目录：每个账号在用户根下有自己的目录，那就是他的工作空间和 Claude 的工作目录；成员只能在自己目录内建项目。目录里的隐藏子目录存属主自己的会话记录、上传、生成媒体等。
- 会话记录：Claude 会话按「属主的配置目录 + 项目的绝对路径」存放，所以项目目录被移动或改名后，旧会话会对不上。
- 临时对话：每条占一只一次性空目录，长期不用会被回收（见 Claude 章「临时对话」）。
- 账号、邀请、额度、审计、用量等授权数据由服务端独占保存，不在任何人的工作空间里，agent 改不到。
- 删除账号时，管理员可选把数据归档或清除。

接口：`files.list`、`files.read`、`sessions.list`

## 连接线路

客户端连服务端有两条线路，安卓 app 会自动切换。

- 局域网直连：手机和服务端在同一个 Wi-Fi 时直接走局域网地址，延迟最低。
- 公网隧道：在外面时走 Cloudflare 隧道。管理员在 服务端控制台 › 服务控制 ›「公网访问」里三选一：「临时地址（试用，重启会换）」（免注册的 trycloudflare 地址，服务端或隧道一重启就换，连过的手机 app 会自动跟过去，网页和分享链接要手动改）、「Cloudflare 隧道」（粘贴隧道令牌）、「自己的域名」（自己的反向代理）。
- 安卓 app 记住服务器的局域网地址与公网地址，回家自动切局域网、出门回隧道；当前线路在 设置 ›「服务器地址」/「当前线路」里看（显示「局域网直连」或隧道）。
- 连不上时顶部出离线提示条，说明原因（这台设备没网、服务器临时地址变了、电脑睡眠或关机等），恢复后自动重连。
- 首次接入：服务端出一张配对二维码，手机 app 首屏点「扫码连接」扫码即以管理员身份连上；二维码 3 分钟有效、只能用一次。

## 部署形态

bridge 服务端有三种部署形态，决定默认值；显式配置一律优先。

| 形态 | 典型场景 | 默认给谁用 | 默认监听 | Claude in Chrome |
|---|---|---|---|---|
| 本机桌面 | 装在自己日常用的电脑上（桌面客户端托管、源码直跑、有图形界面的 Linux / macOS） | 只给我自己 | 所有网卡（同 Wi-Fi 可直连） | 仅 Windows 默认开 |
| 无界面服务器 | Linux systemd 服务、Windows 计划任务、pm2 | 只给我自己 | 仅本机，对外走隧道或反代 | 关 |
| Docker 容器 | docker compose | 只给我自己 | 容器内所有网卡，对外由宿主端口映射决定 | 关 |

- 部署方式：Linux 用一键安装脚本装成 systemd 系统服务或用户服务；Windows 服务器用计划任务托管（不登录也跑）；Docker 用 compose，数据都在一个卷里；也可以装 Windows 桌面客户端选「服务端」（只在用户登录时运行）。
- 多用户要显式打开（「也给别人用」）；部署方也可以接管这个开关（控制台只读显示，怎么切换照部署方的说明）。
- 界面说「电脑」还是「服务器」跟着部署形态走：服务端跑在 Linux / Docker / 声明为服务器的机器上时，断线提示等文案说「服务器」，也不提「睡眠、退出客户端」这类只对电脑成立的原因；Windows 上没有显式声明的一律当成自己的电脑。接口 `whoami` 的 server.hosting 给出同一个结论（host / server）。
- 同一套服务端与前端也给 bridge 的发行版用（如 Muse Bridge）：发行版在 config.json 的 distro 里声明产品名与默认语言，界面上的「The Bridge」整体换成它的名字；`whoami` 的 server.brand / distro 给出来。Linux 服务器上做不到的设置项（如保持唤醒、跟随 Claude Desktop 的归档）直接不显示。
- Claude 认证：在服务端控制台「Claude 账号」里添加；也可以在 Claude 设置的「模型服务」里接自定义 API。
- 服务端控制台（设置 › 服务器 ›「服务端控制台」，仅管理员）分页：总览、活跃进程、用户（多用户关时为服务账号）、额度与注册、会话 / 续聊、定时任务、媒体、Claude 账号、设备、服务控制。服务控制里能重启、一键更新、管理公网访问。

## 设备

设备是登记到 bridge 的电脑（装 Windows 桌面客户端并用同一个账号登录即登记），agent 能通过它操作那台电脑。

- 界面：设置 › 设备 ›「我的设备」列出名字、系统、客户端版本、在线状态；可「断开」「吊销」「删除」。吊销后那台电脑立刻断开，要重新登录才能再连。
- 档位由那台电脑自己定（桌面客户端设置里的「这台电脑」）：「关闭」（服务器上看它是离线）、「只看」（能看屏幕、读界面，动手前先问你）、「操作」（能点键鼠、跑命令、读写文件）。
- 一台设备只给它主人的 agent 用；管理员要查看成员的电脑须成员允许。
- 端口转发：把电脑上的本机端口（dev server、本机模型接口）接到服务器，手机能打开、Claude 能用；只转那台电脑的 127.0.0.1，WebSocket 暂不转。持有地址的人都能访问，不用了就删掉。

接口：`devices.list`、`devices.run`
