# 概览

Muse Bridge（当前版本 {{version}}）是装在 Muse（muse.ai）agent VM 上的网页工作台：用户用手机或电脑的浏览器打开一个网址，就能用 Claude Code 和 dimensio；本章说明它由哪些部分组成、有哪些 agent、谁能用什么、数据放在哪、怎么连上、怎么更新。

## Muse Bridge 是什么

Muse Bridge 是一个开源（MIT）的自托管服务：agent、文件、会话记录都在这台 Muse VM 上运行和保存，浏览器和安卓 app 只是界面。

- 典型用法：在手机上给 VM 上的 Claude 派活（写代码、整理文件、做研究），回到电脑前在浏览器里接着看同一个会话。
- 部署由 Muse 自己做：用户把开场提示词发给 Muse，Muse 下载发布包、问四个问题、用 `deploy/muse/bootstrap.sh` 装好并注册自愈看门狗。
- 可以只给自己用，也可以开多人用、给朋友发邀请码（见 accounts 章）。
- 回答在服务器上跑：浏览器断网、刷新、关掉都不影响这一轮继续，重新打开会接上。

## 组成部分

| 部分 | 是什么 | 说明 |
|---|---|---|
| 服务端 | 跑 agent、存数据的 Node 服务，在 VM 上只听 `127.0.0.1:8787` | 由 systemd 管；对外经 Cloudflare 隧道 |
| 网页 | 浏览器打开公网地址 | 手机是手机布局，电脑大屏是桌面布局；界面跟服务器走，刷新就是最新版 |
| 安卓 app | 在线 WebView 壳 | 把同一个网页装进独立窗口，记得住服务器地址、临时地址变了能直接换；新功能不用更新 app |
| 服务端控制台 | 管理员的管理页面 | 设置 ›「连接」›「服务端控制台」 |

- 没有 iPhone app（用 Safari 添加到主屏幕），也没有 Windows / Mac 桌面客户端。

## 有哪些 agent

Muse Bridge 只有两个 agent，各对应主页上的一个入口。

| id | 名称 | 用什么 | 能否开给注册账号 |
|---|---|---|---|
| `claude` | Claude Code | 服务器配好的 Claude 订阅（Pro / Max），或管理员接的自定义模型服务 | 能（新账号默认就有） |
| `dimensio` | dimensio | 各家模型 API key（Anthropic、OpenAI、Gemini、DeepSeek、Kimi、智谱、通义、小米 MiMo，或任何 OpenAI 兼容服务） | 能，要管理员按人勾选 |

- 装的时候可以只装一个；只装一个或某人只能用一个时没有主页，打开网址直接就是那一页。
- 某个 agent 能不能用 = 装了 ∩ 管理员在 设置 ›「Agent」里开着 ∩ 这个人被授权。不可用的 agent 界面上不出现入口。
- 可用模型：{{models}}

接口：`whoami`、`overview`

## 主页与全局入口

- 主页（两个 agent 都能用时）：左上角 Muse Bridge 字样，右上角账户胶囊，中间 Claude 和 dimensio 两个方块。账户胶囊里有用量、「工作空间」、「设置」、扫一扫登录网页版（手机上）、退出登录。
- 侧栏底部的账户卡（Claude 页）：设置、账户、关于、工作空间、退出登录。
- 工作空间：服务器上的文件管理器（见 workspace 章）。
- 定时触发：让 Claude 按时间表无人值守跑任务（见 routines 章）。
- 设置：见 settings 章。

接口：`ui.view`、`ui.open`、`files.list`、`routines.list`

## 身份与档位

| 身份 | 怎么登录 | 能做什么 |
|---|---|---|
| 管理员 | 管理员访问令牌（装好时结果块里给的那串），或扫码 | 全部功能，不限额；能动整台服务器；服务端控制台、自定义（技能 / 连接器 / 插件）、设置里的 Agent 与模型服务 |
| Pro 账号（完全信任） | 账号密码（Pro 邀请码注册或管理员升档） | 有命令行和终端；只在自己的文件夹里建项目。隔离是「软」的，有命令行就可能读到服务器上共享的凭据，只给完全信任的人 |
| 普通账号 | 账号密码 | Claude 能联网、在自己文件夹里读写，不能跑命令、没有终端 |
| 分享访客 | 打开只读分享链接（`/w/…`） | 只能浏览、预览、下载分享里的文件 |

- 「只自己用」（`set-users solo`）时只有管理员令牌能登录；「多人用」（`set-users multi`）才有注册和邀请码。
- 所有人共用服务器上那一份 Claude 订阅的额度；注册账号另受管理员设的轮数 / 花费额度限制。
- 技能、连接器、插件只对管理员自己的对话生效。

接口：`whoami`、`keys.list`

## 数据放在哪

- 全部数据在 VM 的 `/home/hatch/bridge-srv/`（数据根，跟程序目录分开）：管理员的主工作空间在 `workspace/`，每个注册账号的文件夹在 `users/<账号名>/`。
- 对话里直接上传的附件：管理员的在 `bridge-srv/uploads`，注册账号的在自己文件夹下的隐藏目录 `.bridge` 里。
- 会话记录按「属主 + 项目文件夹的绝对路径」存放，项目文件夹被移动或改名后旧会话会对不上。
- 账号、邀请码、额度、登录会话（含 agent 密钥的哈希）由服务端独占保存，不在任何人的工作空间里，agent 改不到。
- 删账号时管理员可以选只删账号、保留文件夹，或连文件夹一起删。
- 这是 Muse 的 VM，不是正式服务器：别放重要数据。

接口：`files.list`、`files.read`、`sessions.list`

## 怎么连上：公网地址

- 用户打开的网址经 Cloudflare 隧道接到 VM 上的服务。两种：
  - **临时地址**（`https://….trycloudflare.com`）：零配置；VM 每隔几个小时被平台重启一次，地址会跟着变，变了 Muse 会主动告诉用户新地址。
  - **自己的域名**（托管在 Cloudflare 的固定地址）：地址不变，Muse 带用户在 Cloudflare 后台建一条隧道。
- 登录状态跟着网址存：换了地址要在新地址重新登录一次，令牌和账号密码不变。
- 安卓 app 连不上时会出「连不上服务器」面板，点「更换地址」粘新地址。
- 页面顶部出现「离线 · 连不上服务器…」：网断了、服务在重启，或临时地址已经换了；页面会自己重试。
- 公网地址、隧道、域名都由 Muse 用 `bootstrap.sh` 管，界面里没有「公网访问」设置。

## 更新、看门狗与重启

- 更新：有新版本时 Muse 会用一两句话告诉用户更新了什么，问要不要更新；用户说「更新」就行，也可以开自动更新。更新会等没人在聊天时才切换，新版本起不来会自动退回。界面里没有「更新」按钮。
- 页面由服务器直接提供：服务器更新后刷新页面就是新版，安卓 app 也一样。
- 看门狗：VM 重启后在 60 秒内把服务拉起来。正在跑的 Claude 对话会被打断（提示「这一轮被中断」，说一句「继续」就行）；dimensio 会自动接着做。
- 重启服务：服务端控制台 ›「服务控制」›「重启服务」（空闲时重启 / 立即重启）。
- 已知问题与绕过办法随更新频道下发，Muse 能查到（`bootstrap.sh known-issues`）。

## Muse VM 的限制

- 出站只能经 HTTP CONNECT 代理；VM 第一次访问某个网站时，用户要在 Muse 里批一张「允许 Muse 与 … 分享信息？」审核卡（选「总是允许此站点」就不再问）。对话一直「等待模型回复」多半是有张卡没批。
- 起不了浏览器沙箱：agent 没有「打开网页、截图、操作浏览器」这类工具；联网搜索和抓网页文字照常可用。
- 不能跑 Docker。
- 定时任务按服务器时区（一般是 UTC）。

## 问题反馈

- 网页里 设置 ›「反馈」›「报告问题或提建议」›「报告」：一句话就行，不用 GitHub 账号，会提交到项目公开的 GitHub Issues（安全问题私下发给维护者）。只带版本、服务状态、程序自己的报错位置和出错前几步操作，不含对话、文件、key 和地址；发送前可以「查看会发送的内容」。
- 页面出错时，错误提示条上有「报告问题」按钮。
- 也可以直接跟 Muse 说，Muse 先判断是不是已知问题，出草稿给用户看，同意了才发。
- 管理员可以打开「出错时自动发送错误报告」（同一个错误每个版本只报一次）。
